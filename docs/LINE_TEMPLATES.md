# LINE Official Account — Rich Menu และข้อความทั้งหมด

เอกสารนี้รวมข้อความทุกฉบับที่ระบบใช้ ในรูปแบบที่คัดลอกไปวางได้เลย

**หลักการที่ยึดตลอดทั้งเอกสาร**

- ข้อความที่ส่งเข้ากลุ่มภายใน (resident, แอดมิน) มีเฉพาะ **referral ID กลุ่ม สถานะ และลิงก์** เท่านั้น
- ข้อความที่ตอบกลับแพทย์ต้นทาง **ไม่มีชื่อผู้ป่วยและ HN** อ้างอิงด้วย referral ID
- ข้อยกเว้นเดียวคือการแจ้ง fellow กลุ่มที่ 1 ซึ่งอาจารย์อนุมัติให้ส่ง **เพศ อายุ โรค** ได้
- ทุกข้อความที่ส่งถึงแพทย์ต้นทางต้องมีข้อความว่า **ไม่ใช่ช่องทางฉุกเฉิน**

> **ข้อความทั้งหมดควรเก็บในชีต `config`** ไม่ใช่ฝังในโค้ด
> เพื่อให้แพทย์แอดมินแก้ไขเองได้โดยไม่ต้องพึ่งโปรแกรมเมอร์ (SRS NFR-005)
> คอลัมน์: `key` · `message_template` · `updated_by` · `updated_at`

## 0. สร้าง LINE Official Account ตั้งแต่ต้น

ทำครั้งเดียวตอนเริ่มระบบ ใช้เวลาราว 20–30 นาที
อ้างอิงจากเอกสารทางการของ LINE (ตรวจเมื่อ 11 ส.ค. 2569 — ขั้นตอนนี้เปลี่ยนจากของเดิม
ที่เคยสร้าง channel ใน Developers Console โดยตรง)

### ขั้นที่ 1 — สมัคร LINE Business ID

ไปที่ https://account.line.biz/signup

เลือกสมัครด้วย **บัญชี LINE ที่มีอยู่** (ง่ายกว่าและผูกกับมือถือที่ใช้อยู่แล้ว)
หรือด้วยอีเมลก็ได้

> ใช้บัญชีที่เป็นของหน่วยงานหรือของผู้ดูแลระบบระยะยาว **อย่าใช้บัญชีส่วนตัวของคนที่จะย้ายไป**
> เพราะเจ้าของบัญชีคือคนที่กู้คืนสิทธิ์ได้เมื่อมีปัญหา

### ขั้นที่ 2 — สร้าง LINE Official Account

ที่ https://manager.line.biz → **สร้างบัญชีใหม่ / Create new account**

| ช่อง | ใส่อะไร |
| --- | --- |
| ชื่อบัญชี | เช่น `ส่งต่อผู้ป่วยโลหิตวิทยา ศิริราช` — ชื่อนี้แสดงในแชทของแพทย์ต้นทาง |
| อีเมล | อีเมลผู้ดูแล |
| ประเทศ | ไทย |
| ประเภท | องค์กร / โรงพยาบาล |

เสร็จแล้วจะเข้าหน้า LINE Official Account Manager ของบัญชีนี้

### ขั้นที่ 3 — เปิดใช้ Messaging API

ยังอยู่ใน **LINE Official Account Manager** → **Settings (ตั้งค่า)** → **Messaging API**
→ กด **Enable Messaging API / ใช้ Messaging API**

จะถูกถามให้ **เลือก Provider**

> ⚠️ **สำคัญที่สุดในทั้งเอกสารนี้**
> เอกสาร LINE ระบุว่า Provider ที่เลือกตรงนี้ **เปลี่ยนหรือถอดออกภายหลังไม่ได้**
> ("can't be changed or de-assigned")
>
> ถ้าวันหลังจะทำ **LINE Login + LIFF** เพื่อให้ระบบส่ง LINE ถึงแพทย์ต้นทาง
> รายบุคคลได้ (ดู §6.4 ช่องว่างที่ 2) **ต้องอยู่ใต้ Provider เดียวกันนี้**
> ตั้งชื่อ Provider เป็นชื่อหน่วยงาน เช่น `สาขาวิชาโลหิตวิทยา ศิริราช`
> ไม่ใช่ชื่อโปรเจกต์หรือชื่อบุคคล

การเปิดตรงนี้จะสร้าง **Messaging API channel** ให้อัตโนมัติ

### ขั้นที่ 4 — ปิดระบบตอบกลับอัตโนมัติของ LINE

ยังอยู่ใน **LINE Official Account Manager** → **Settings** → **Messaging API Settings**

ปิดทั้งสองอย่าง:

- **Greeting messages** (ข้อความทักทายเมื่อเพิ่มเพื่อน)
- **Auto-reply messages** (ตอบกลับอัตโนมัติ)

ถ้าไม่ปิด ระบบของ LINE จะตอบชนกับบอทของเรา ผู้ใช้จะได้ข้อความซ้อนสองฉบับ
และคำสั่ง `#id` จะใช้ไม่ได้

> ข้อความทักทายที่เราต้องการอยู่ใน §2 ของเอกสารนี้ — ตั้งเป็น
> Greeting message ของ LINE ก็ได้ แต่ต้องเลือกอย่างใดอย่างหนึ่ง ไม่ใช่ทั้งคู่

### ขั้นที่ 5 — เอา Channel access token

ไปที่ https://developers.line.biz/console → เลือก Provider → เลือก channel ที่เพิ่งสร้าง
→ แท็บ **Messaging API** → เลื่อนลงหา **Channel access token (long-lived)** → กด **Issue**

คัดลอกไปวางที่ **Apps Script → ⚙️ Project Settings → Script Properties**

| Property | ค่า |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | token ที่เพิ่ง issue |

> token ยาวมาก (ราว 170 ตัวอักษร) คัดลอกให้ครบทั้งบรรทัด
> ถ้ากด Issue ซ้ำ token เดิมจะใช้ไม่ได้ทันที ต้องเอาตัวใหม่ไปแทน

### ขั้นที่ 6 — ตั้ง Webhook

แท็บ **Messaging API** เดิม → หัวข้อ **Webhook settings** → กด **Edit** ที่ Webhook URL

ใส่ค่าเดียวกับ `BOOKING_API_URL` ใน `.env.local` (Apps Script Web App URL — ตัวเดียวกัน
ไม่ต้อง deploy แยก) ดูด้วยคำสั่ง:

```bash
grep '^BOOKING_API_URL=' .env.local
```

จากนั้น:

1. กด **Verify** → ต้องขึ้น **Success**
2. เปิดสวิตช์ **Use webhook**

**ถ้า Verify ไม่ผ่าน** ให้เปิด URL นั้นในเบราว์เซอร์ก่อน ต้องเห็นข้อความ
`OK — endpoint นี้รับเฉพาะคำสั่งแบบ POST` พร้อมบรรทัด `version:`
ถ้าไม่เห็น แปลว่า Apps Script ยังไม่ได้ deploy หรือ deploy ไม่ใช่แบบ
"Anyone" (ดู §การติดตั้ง ในหัวไฟล์ `apps-script/Api.gs`)

### ขั้นที่ 7 — เปิดให้บอทเข้ากลุ่มได้ (ข้ามได้ถ้ายังไม่ใช้กลุ่ม)

แท็บ **Messaging API** เดิม → **Allow bot to join group chats** → เปิด

**ปิดไว้เป็นค่าเริ่มต้น** ถ้าไม่เปิด เชิญบอทเข้ากลุ่มไม่ได้เลย

ข้ามขั้นนี้ได้ถ้าใช้วิธีส่งเข้าแชทตัวต่อตัวตาม §6.4

### ขั้นที่ 8 — ผูกปลายทางการแจ้งเตือน

แอด LINE OA เป็นเพื่อน (QR code อยู่ใน OA Manager → หน้าแรก) → พิมพ์ `#id` ในแชท
→ เอา ID ที่บอทตอบมาใส่ Script Property ชื่อ `LINE_TARGET_ADMIN`

รายละเอียดและทางเลือกอื่นดู §6.4

### ขั้นที่ 9 — ทดสอบ

ใน Apps Script เลือกฟังก์ชัน **`sendDailyBatch`** แล้วกด **Run**

ควรได้ข้อความสรุปคิวเข้า LINE ทันที ถ้าไม่มา ดูที่ **Executions** จะเห็นสาเหตุ

---

### สรุปสิ่งที่ต้องมีครบก่อนใช้งานจริง

| ที่ | ต้องเป็น |
| --- | --- |
| Script Property `LINE_CHANNEL_ACCESS_TOKEN` | มีค่า |
| Script Property `LINE_TARGET_ADMIN` | มีค่า |
| Developers Console → Use webhook | เปิด |
| Developers Console → Webhook URL | ตรงกับ `BOOKING_API_URL` |
| OA Manager → Auto-reply messages | **ปิด** |
| OA Manager → Greeting messages | **ปิด** (หรือใช้ข้อความใน §2) |

## 1. Rich Menu

ขนาดภาพ **2500 × 1686 px** แบ่ง 6 ช่อง (3 คอลัมน์ × 2 แถว)
แถวบนคือ 4 กลุ่มหลัก แถวล่างคือช่องทางช่วยเหลือ

```
┌───────────────┬───────────────┬───────────────┐
│  🧬 กลุ่ม 1    │  💊 กลุ่ม 2    │  🏥 กลุ่ม 3    │
│  นัดพบแพทย์    │  ขอความเห็น    │  ขอส่งตัวมา    │
│  ปลูกถ่ายฯ     │  สูตรยาเคมี    │  ให้ยาเคมี     │
├───────────────┼───────────────┼───────────────┤
│  🌐 กลุ่ม 4    │  ❓ ไม่แน่ใจ    │  ☎️ ติดต่อ     │
│  Refer อื่น ๆ  │  ว่าเข้ากลุ่มไหน │  เจ้าหน้าที่    │
└───────────────┴───────────────┴───────────────┘
```

### การตั้งค่าแต่ละช่อง

| ช่อง | ประเภท action | ค่า |
| --- | --- | --- |
| 🧬 กลุ่ม 1 | URI | `https://sibmt-refer.uradev222.workers.dev/refer/transplant` |
| 💊 กลุ่ม 2 | URI | `https://sibmt-refer.uradev222.workers.dev/refer/regimen-consult` |
| 🏥 กลุ่ม 3 | URI | `https://sibmt-refer.uradev222.workers.dev/refer/chemo-admission` |
| 🌐 กลุ่ม 4 | URI | `https://sibmt-refer.uradev222.workers.dev/refer/general` |
| ❓ ไม่แน่ใจ | Message | `ไม่แน่ใจว่าเข้ากลุ่มไหน` |
| ☎️ ติดต่อ | Message | `ขอติดต่อเจ้าหน้าที่` |

> ลิงก์ชี้ไป**หน้ารายละเอียดของกลุ่ม** ไม่ใช่ Google Form โดยตรง
> เพื่อให้แพทย์เห็น checklist เอกสารและดาวน์โหลดหนังสือรับทราบก่อนกรอก

ตั้ง Rich Menu เป็นค่าเริ่มต้นสำหรับผู้ใช้ทุกคน (`setDefaultRichMenu`)

## 3. ตอบกลับอัตโนมัติเมื่อพิมพ์ข้อความในแชท

> ⚠️ **§3.1–3.3 ยังเป็นแค่ข้อความร่าง ยังไม่มีโค้ดตัวไหนส่งมัน**
> ตรวจแล้วเมื่อ 22 ส.ค. 2569 — ไม่มีฟังก์ชันใดใน `apps-script/` อ่านคีย์
> `auto_reply_*` เลย ส่วน §3.4 ข้างล่างทำงานจริงแล้ว
>
> **อย่าเปิด Auto-reply messages ของ LINE เพื่อเอาข้อความ §3.1–3.3 มาใช้**
> ตามขั้นที่ 4 ในการติดตั้ง ต้องปิดไว้ ไม่งั้นแพทย์ที่พิมพ์รหัสอ้างอิงเข้ามา
> จะได้สองข้อความพร้อมกัน คือสถานะเคสจากบอท กับข้อความ §3.3 ที่บอกว่า
> "ระบบนี้ยังไม่รองรับการตอบคำถามในแชท" ซึ่งขัดกันเอง

### 3.1 เมื่อพิมพ์ "ไม่แน่ใจว่าเข้ากลุ่มไหน"

**key:** `auto_reply_unsure`

```text
ไม่เป็นไรค่ะ 🙂 เจ้าหน้าที่ช่วยคัดกรองให้ได้

กรุณาโทร 02-419-9903 (จันทร์–ศุกร์ 08:00–16:00 น.)
หรือพิมพ์คำถามทิ้งไว้ในแชทนี้ เจ้าหน้าที่จะติดต่อกลับในวันทำการถัดไป

ตัวอย่างเรื่องที่สอบถามได้ก่อนตัดสินใจส่งตัว
• ไม่แน่ใจว่าเคสนี้ควร refer หรือดูแลต่อที่โรงพยาบาลได้เอง
• อยากทราบว่าขณะนี้ศิริราชมีการศึกษาวิจัยที่เหมาะกับผู้ป่วยหรือไม่
• ไม่แน่ใจว่าเรื่องที่ต้องการเข้ากลุ่มใดใน 4 กลุ่ม

🔒 กรุณาอย่าพิมพ์ชื่อ-สกุล หรือเลข HN ของผู้ป่วยในแชทนี้
```

### 3.2 เมื่อพิมพ์ "ขอติดต่อเจ้าหน้าที่"

📞 ธุรการ OPD 700 โลหิตวิทยา โรงพยาบาลศิริราช
โทร 02-419-9903
เวลาทำการ จันทร์–ศุกร์ 08:00–16:00 น.

เจ้าหน้าที่จะติดต่อกลับในวันทำการถัดไปค่ะ

⚠️ กรณีฉุกเฉิน กรุณาใช้ช่องทางส่งต่อฉุกเฉินระหว่างโรงพยาบาลตามปกติ

### 3.4 เมื่อพิมพ์รหัสอ้างอิงเข้ามา — บอทตอบสถานะให้ ✅ ใช้งานได้แล้ว

ทำในโค้ด ไม่ใช่ในหน้าตั้งค่าของ LINE — อยู่ที่ `apps-script/LineWebhook.gs`

**เงื่อนไขที่บอทจะตอบ**

- ข้อความมีรหัสรูปแบบ `HEM-ปีเดือนวัน-ลำดับ` อยู่ที่ไหนก็ได้ในข้อความ
  ก๊อปมาทั้งบรรทัดจากอีเมลได้เลย ไม่ต้องพิมพ์รหัสเดี่ยว ๆ
- **เฉพาะแชทตัวต่อตัวเท่านั้น** ในกลุ่มบอทจะเงียบ เพราะกลุ่ม resident
  มีรหัสอ้างอิงลอยอยู่เต็มจากรอบแจ้งเตือน 10:00 น. ถ้าตอบทุกครั้งกลุ่มจะรก
  และคนในหน่วยเปิด dashboard ดูได้อยู่แล้ว
- ค้นได้ไม่เกิน 20 ครั้งต่อชั่วโมงต่อหนึ่งคู่สนทนา

**ตัวอย่างข้อความที่บอทตอบ**

```text
เคส HEM-20260822-0001
กลุ่มที่: 2
สถานะ: รออาจารย์อนุมัติ
ส่งเมื่อ: 22 ส.ค. 2569 09:14 น.

ทีมงานรับเรื่องในรอบประจำวันเวลา 10:00 น. ของวันทำการ
และตอบกลับภายใน 48 ชั่วโมงทำการ

สอบถามเพิ่มเติม โทร 02-419-9903 (จันทร์-ศุกร์ 08:00-16:00 น.)
```

**หาไม่เจอ**

```text
ไม่พบเคสรหัส HEM-20260822-9999

กรุณาตรวจว่าพิมพ์ครบถ้วนตามที่ได้รับทางอีเมล
รูปแบบคือ HEM-ปีเดือนวัน-เลขลำดับ เช่น HEM-20260822-0001

ถ้ายังไม่พบ โทร 02-419-9903 (จันทร์-ศุกร์ 08:00-16:00 น.)
```

**สิ่งที่บอทไม่ตอบเด็ดขาด** — ข้อมูลผู้ป่วยทุกชนิด ชื่อโรงพยาบาลต้นทาง
ชื่อแพทย์ผู้ส่ง และ**เนื้อคำแนะนำของอาจารย์** คำแนะนำเป็นเนื้อหาทางคลินิก
ส่งทางอีเมลอย่างเดียว ทาง LINE บอกได้แค่ว่า "ส่งกลับทางอีเมลแล้ว" (PDPA-003)

รหัสอ้างอิงเดาได้ เพราะเป็นเลขลำดับไล่จาก 0001 ของแต่ละวัน คำตอบจึงตั้งใจ
ให้ไม่มีอะไรที่คนเดาถูกแล้วได้ประโยชน์ — รู้แค่ว่ามีเคสกลุ่มไหนสถานะอะไร
ไม่รู้ว่าเป็นผู้ป่วยคนไหนหรือใครส่งมา

**ไม่ต้องเก็บ LINE ID ของใครเลย** — การตอบกลับใช้ `replyToken` ที่ LINE
แนบมากับข้อความ ใช้ได้ครั้งเดียว หมดอายุใน 1 นาที ระบบจึงตอบได้โดยไม่ต้องรู้
ว่าใครถาม และไม่ได้บันทึกอะไรลงชีตเลย

## 6.4 ปลายทางของข้อความภายใน — ตั้งตัวเดียวก็เริ่มใช้ได้

**ไม่จำเป็นต้องสร้างกลุ่ม LINE** ช่อง `to` ของ LINE push รับได้ทั้ง groupId และ
userId ระบบจึงส่งเข้าแชทตัวต่อตัวได้เหมือนกัน

### แบบเร็วที่สุด — ตั้งค่าเดียว

1. แอด LINE OA เป็นเพื่อนจากบัญชีของแอดมินกลาง
2. พิมพ์ `#id` ในแชทตัวต่อตัวนั้น
3. เอา ID ที่บอทตอบมาใส่ Script Property ชื่อ **`LINE_TARGET_ADMIN`**

### มีแอดมินหลายคน — คั่นด้วยจุลภาค

ช่องเดียวใส่ได้หลายปลายทาง ทุกคนจะได้รับข้อความเดียวกันพร้อมกัน

```
LINE_TARGET_ADMIN = Uxxxxxxxx,Uyyyyyyyy
```

เหมาะกับกรณีที่คนติดตั้งระบบอยากคอยดูให้ด้วย ควบคู่กับแอดมินตัวจริง
โดยไม่ต้องสร้างกลุ่ม LINE และไม่ต้องเปิดสิทธิ์ให้บอทเข้ากลุ่ม

- ใส่ **userId** หรือ **groupId** ปนกันก็ได้ ระบบไม่แยก
- ใส่ ID ซ้ำกันจะส่งครั้งเดียว ไม่ส่งซ้ำ
- ปลายทางหนึ่งพัง (เช่น บล็อกบัญชี หรือออกจากกลุ่มไปแล้ว) คนที่เหลือยังได้รับ
  และ Executions จะบันทึกไว้ว่าปลายทางไหนพัง
- แต่ละปลายทางนับเป็นหนึ่งข้อความในโควตาของ LINE

เท่านี้ได้รับ**ครบทุกการแจ้งเตือน** เพราะข้อความที่ยังไม่มีปลายทางเฉพาะจะตกมาที่นี่
พร้อมบรรทัดกำกับว่า `(ส่งถึงคุณเพราะยังไม่ได้ตั้ง LINE_TARGET_RESIDENT)`
เพื่อให้รู้ว่าข้อความนั้นตั้งใจส่งถึงใคร และรู้ว่ายังตั้งค่าไม่ครบ

### ค่อยแยกปลายทางทีหลัง

เมื่อมีกลุ่มจริงแล้วค่อยเพิ่ม `LINE_TARGET_RESIDENT` และ `LINE_TARGET_FELLOW`
ข้อความจะย้ายไปกลุ่มนั้นเองทันที ไม่ต้องแก้โค้ด

| Property | รับอะไร | ควรใส่อะไร | ถ้าไม่ตั้ง |
| --- | --- | --- | --- |
| `LINE_TARGET_ADMIN` | Red Alert 48 ชม. + ปัญหาการตั้งค่า | **userId ราย 1–2 คน** คั่นจุลภาค | **เงียบทั้งหมด** |
| `LINE_TARGET_RESIDENT` | สรุปคิวค้างรอบ 10:00 น. | **groupId** ของกลุ่มแจ้งเตือน | ตกไปที่ `LINE_TARGET_ADMIN` |
| `LINE_TARGET_FELLOW` | มีผู้ป่วยจองคิวมาพบ | **groupId** ของกลุ่ม fellow | ตกไปที่ `LINE_TARGET_ADMIN` |

### ทำไม ADMIN ไม่ควรเป็นกลุ่ม แต่อีกสองช่องควรเป็น

**`_RESIDENT` และ `_FELLOW` เป็นการแจ้ง "ทีม"** — สรุปคิวค้างและคิวที่จองเข้ามา
เป็นเรื่องที่ทั้งทีมควรเห็นพร้อมกันและคุยต่อได้ในที่เดียว ว่าใครรับเคสไหนไป
ถ้าส่งแยกรายคน แต่ละคนจะไม่รู้ว่าคนอื่นเห็นหรือยัง และคนหมุนเวียนทุกปีการศึกษา
การแก้ที่สมาชิกกลุ่มไม่ต้องแตะ Script Property เลย

**`_ADMIN` เป็นการแจ้ง "ผู้รับผิดชอบ"** — Red Alert คือตาข่ายนิรภัยชั้นสุดท้าย
เมื่อเคสค้างเกิน 48 ชั่วโมงทำการ ต้องถึงตัวคนที่รับผิดชอบจริง ไม่ใช่ห้องที่ทุกคน
คิดว่าคนอื่นจะจัดการ (SRS กำหนดให้มีทั้งแอดมินกลางและผู้สำรองด้วยเหตุผลนี้)
จึงควรเป็น userId ของแอดมินกลางกับผู้สำรอง คั่นจุลภาค — ทั้งคู่ได้รับพร้อมกัน
และไม่มีใครหลุดออกจากกลุ่มโดยไม่มีใครรู้

⚠️ **ถ้าไม่ตั้งสักตัวเดียว** ระบบยังทำงานปกติทุกอย่าง (จองคิว ตอบเคส อีเมลถึง
แพทย์ต้นทาง) แต่การแจ้งเตือนภายในจะเงียบสนิท — ไม่มีใครรู้ว่ามีเคสรอตอบ
นอกจากเปิด dashboard ดูเอง และ Red Alert 48 ชั่วโมงจะไม่ทำงาน
ข้อความจะถูกเขียนลง Apps Script → Executions แทน

## 6.5 วิธีหา group ID ของทั้ง 3 กลุ่ม (เมื่อพร้อมแยกปลายทาง)

`LINE_TARGET_RESIDENT` / `LINE_TARGET_ADMIN` / `LINE_TARGET_FELLOW` เป็น **group ID**
ซึ่ง **ไม่มีให้ดูที่ไหนในแอป LINE เลย** ดูได้ทางเดียวคือดักจาก webhook

ระบบมีตัวช่วยไว้แล้ว ทำตามนี้ทีละกลุ่ม:

1. เชิญ LINE OA เข้ากลุ่ม (เมนู "เชิญ" ในกลุ่มนั้น)
2. พิมพ์ `#id` ลงในกลุ่ม
3. บอทจะตอบกลับมาในกลุ่มนั้นเลย เช่น

   ```
   ID ของที่นี่คือ
   Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

   ประเภท: group

   นำไปวางที่ Apps Script → Project Settings → Script Properties
   ชื่อ: LINE_TARGET_RESIDENT หรือ LINE_TARGET_ADMIN หรือ LINE_TARGET_FELLOW
   ```

4. คัดลอกบรรทัด ID ไปวางใน **Apps Script → ⚙️ Project Settings → Script Properties**
   โดยตั้งชื่อตามหน้าที่ของกลุ่มนั้น

ทำซ้ำกับอีก 2 กลุ่ม

**ถ้าพิมพ์ `#id` แล้วบอทเงียบ** ให้ไล่ตามลำดับนี้:

| อาการ | สาเหตุที่พบบ่อย |
| --- | --- |
| เงียบสนิท | ยังไม่ได้ตั้ง Webhook URL หรือยังไม่ได้เปิด "Use webhook" |
| เงียบเฉพาะในกลุ่ม แต่ตอบตัวต่อตัวได้ | ยังไม่ได้เปิด "Allow bot to join group chats" ใน **LINE Developers Console → แท็บ Messaging API** (ปิดไว้เป็นค่าเริ่มต้น) |
| ตอบว่าไม่มี token | ยังไม่ได้ใส่ `LINE_CHANNEL_ACCESS_TOKEN` ใน Script Properties |
| ตอบช้ามาก แล้วเงียบ | replyToken หมดอายุแล้ว (มีอายุ 1 นาที) — พิมพ์ `#id` ใหม่อีกครั้ง |

ดูสาเหตุจริงได้ที่ Apps Script → **Executions** ทุก event ที่เข้ามาถูกบันทึกไว้

> `#id` ตอบเฉพาะ ID ของห้องที่คนถามอยู่แล้ว ไม่ได้เปิดเผยอะไรที่คนในห้องนั้นไม่รู้
> และไม่แตะชีตเลย จะเก็บไว้ใช้ตอนเพิ่มกลุ่มใหม่ในอนาคตก็ได้
> ถ้าอยากปิด ให้ลบบล็อก `if (text === LINE_WHOAMI_KEYWORD)` ใน `apps-script/Api.gs`
