## 2. ระบบนี้คืออะไร และไม่ใช่อะไร

### เป็นอะไร

ระบบประสานงานการส่งต่อผู้ป่วยจากโรงพยาบาลต้นทางมายังสาขาวิชาโลหิตวิทยา ศิริราช
แบ่งงานเป็น 4 กลุ่มตาม **สิ่งที่แพทย์ต้นทางต้องการ** ไม่ใช่ตามชื่อโรค

| กลุ่ม | ต้องการอะไร | เข้าระบบทางไหน | ใครตอบ |
|---|---|---|---|
| **1** | นัดพบแพทย์ปลูกถ่ายเซลล์ต้นกำเนิด | เว็บ `/book/transplant` (จองคิวเอง) | ระบบยืนยันอัตโนมัติ + แจ้ง fellow |
| **2** | ขอความเห็นสูตรยาเคมีบำบัด หรือคำถามอื่น | Google Form | resident ตอบ โดยมีอาจารย์รับรอง |
| **3** | ขอส่งตัวมารับยาเคมีบำบัด/ยากดภูมิ | Google Form | resident ตอบและนัด OPD 700 |
| **4** | ตรวจ OPD ทั่วไป | **ไม่เข้าระบบนี้** — ใช้ระบบนัดหมายของโรงพยาบาล | — |

### ไม่ใช่อะไร — ข้อนี้สำคัญที่สุด

**ระบบนี้ไม่ใช่เวชระเบียน และไม่ใช่ระบบวินิจฉัยโรค**

เวชระเบียนตัวจริงอยู่ใน HIS ของโรงพยาบาลทั้งต้นทางและศิริราชอยู่แล้ว
ระบบนี้เก็บเฉพาะ **ข้อมูลประสานงาน** ซึ่งมีผลตามมาที่สำคัญมาก

- ไม่ต้องเก็บตามระยะเวลาของเวชระเบียน
- **ลบข้อมูลได้โดยไม่ทำให้ประวัติการรักษาของผู้ป่วยหายไป** เพราะ HIS เก็บไว้แล้ว
- ยิ่งเก็บนานยิ่งเป็นภาระและความเสี่ยงโดยไม่ได้ประโยชน์เพิ่ม

**ระบบไม่เคยเก็บ ชื่อผู้ป่วย · HN · เลขบัตรประชาชน · วันเกิดแบบเต็ม**
ทั้งในฟอร์ม ในชีต และในเอกสารแนบ — ข้อนี้เป็นข้อตกลงตั้งแต่วันแรกและห้ามเปลี่ยน

## 3. ภาพรวมสถาปัตยกรรม

```
แพทย์ต้นทาง                     เจ้าหน้าที่ศิริราช
     │                                  │
     ├── Google Form (กลุ่ม 2,3) ────┐   │
     │                              ▼   ▼
     ├── เว็บ /book (กลุ่ม 1) ──►  Cloudflare Worker (Next.js)
     │                                  │  อ่านชีต: อ่านอย่างเดียว
     └── LINE OA ──► Apps Script ◄──────┘  เขียนชีต: ผ่าน Apps Script เท่านั้น
                          │
                          ▼
                 Google Sheet (ไฟล์ข้อมูลผู้ป่วย)
                 Google Drive (ไฟล์แนบคำตอบ)
```

### สามส่วน แยกหน้าที่กันชัดเจน

**1. เว็บ (Cloudflare Workers + Next.js 16)**
หน้าเว็บสาธารณะและหลังบ้าน อ่านข้อมูลจากชีตโดยตรงผ่าน Google Sheets API
**แต่เขียนไม่ได้** — service account มีสิทธิ์ Viewer เท่านั้นบนไฟล์ข้อมูลผู้ป่วย

**2. Apps Script (ผูกกับ Google Sheet)**
เป็นตัวเดียวที่เขียนลงไฟล์ข้อมูลผู้ป่วยได้ ทำหน้าที่ทั้ง
- รับคำสั่งจากเว็บผ่าน `doPost` (จองคิว, บันทึกคำตอบ, ตรวจสมาชิก LINE)
- รับ webhook จาก LINE
- งานตามเวลา (แจ้งเตือน, คำนวณ SLA, ถอดชื่อข้อมูล)

**3. Google Workspace**
Sheet เก็บข้อมูล · Form รับข้อมูล · Drive เก็บไฟล์แนบ

### ⚠️ ทำไมเว็บถึงเขียนชีตเองไม่ได้ — เหตุผลสำคัญ

**ไม่ใช่เพราะเรื่องสิทธิ์อย่างเดียว แต่เพราะ `LockService`**

Apps Script ล็อกได้ ทำให้ "ตรวจว่าคิวยังว่าง" กับ "เขียนแถวจอง" เกิดในจังหวะเดียวกัน
สองคนกดจองคิวสุดท้ายพร้อมกันจึงไม่ได้ทั้งคู่

Google Sheets API เปล่า ๆ ทำแบบนี้ไม่ได้ — จะจองเกินโควตาแบบเงียบ ๆ
โดยไม่มีอะไรฟ้อง แล้วผู้ป่วยสองคนจะมาถึง OPD 700 ในสล็อตเดียวกัน

ราคาที่จ่ายคือช้ากว่า (1–10 วินาทีต่อครั้ง) แต่การจองเกิดครั้งเดียวต่อเคส จึงยอมรับได้

### ⚠️ ไฟล์ชีตมีสองไฟล์ ไม่ใช่ไฟล์เดียว

| ไฟล์ | มีอะไร | สิทธิ์ของ service account |
|---|---|---|
| **ไฟล์ข้อมูลผู้ป่วย** | referrals, advice_library, config, ฯลฯ | **Viewer** — ห้ามเปลี่ยนเป็น Editor |
| **ไฟล์ตารางเวร fellow** | fellow_schedule, fellows | **Editor** |

แยกกันเพื่อให้เว็บเขียนตารางเวรได้โดยตรง (เพราะไม่มีข้อมูลผู้ป่วย)
ในขณะที่ไฟล์ข้อมูลผู้ป่วยยังอ่านอย่างเดียวตลอดไป

**ห้ามเอาข้อมูลผู้ป่วยไปไว้ในไฟล์ตารางเวรเด็ดขาด** เพราะไฟล์นั้นเว็บเขียนได้

### 🔒 กฎเรื่องความลับ

- **ห้าม commit** `.env.local`, `.env`, ไฟล์ JSON ของ service account (gitignore ไว้แล้ว)

- **Google Sheet ต้องเป็น "Restricted"** แชร์ทีละอีเมล ห้ามตั้ง "ทุกคนที่มีลิงก์"

## 6. Apps Script — ไฟล์และฟังก์ชัน

### ⚠️ ต้นฉบับของโค้ดคือ repo นี้ ไม่ใช่หน้าจอ Apps Script

Apps Script ไม่มีระบบ version ต่อไฟล์ วิธีทำงานที่ตกลงกันคือ

1. แก้ในโฟลเดอร์ `apps-script/` ของ repo
2. คัดลอกทั้งไฟล์ไปวางทับในหน้าจอ Apps Script
3. กด **Cmd+S** ทุกไฟล์
4. Run `checkCodeFiles()` เพื่อยืนยันว่าครบ
5. Deploy เวอร์ชันใหม่ (เฉพาะเมื่อแก้สิ่งที่เว็บหรือ LINE เรียก)

**ถ้าแก้ในหน้าจอ Apps Script โดยไม่แก้ใน repo การแก้นั้นจะหายในรอบวางทับครั้งถัดไป**

## 9. วิธี deploy และกับดักที่เคยเจอมาแล้ว

### ฝั่งเว็บ

```bash
npm run cf:deploy
```

ตรวจก่อนเสมอ: `npx tsc --noEmit && npx eslint src && npm run build`

**ดูหน้าเว็บบนเครื่องตัวเองโดยไม่แตะข้อมูลจริง**

```bash
npm run dev:demo
```

คำสั่งนี้ล้างค่า credential ทั้งหมดตอนรัน ระบบจึงใช้ข้อมูลสมมติและไม่ต้องล็อกอิน
— เปิดที่ `localhost:3111` ใช้ตรวจงานได้โดยไม่ต้องใช้รหัสผ่านจริงและไม่แตะชีตจริง

### ฝั่ง Apps Script

1. วางไฟล์ที่แก้ทับในหน้าจอ Apps Script → **Cmd+S ทุกไฟล์**
2. Run `checkCodeFiles()`
3. **Deploy → จัดการการทำให้ใช้งานได้ → ✏️ → เวอร์ชันใหม่ → ทำให้ใช้งานได้**
4. เปิด `/exec` ในเบราว์เซอร์ ตรวจว่าเลขเวอร์ชันขยับ

### ⚠️ กับดักที่เสียเวลามาแล้วจริง ๆ ทั้งหมดนี้

**1. กด "New deployment" แทน "เวอร์ชันใหม่ของ deployment เดิม"**
จะได้ URL ใหม่ แล้ว `BOOKING_API_URL` กับ LINE webhook จะยังชี้ไปที่ของเก่า
ระบบเงียบไปเฉย ๆ โดยไม่มี error

**2. วางโค้ดแล้วลืม `Api.gs`**
`API_VERSION` อยู่ในไฟล์นั้นไฟล์เดียว เลขเวอร์ชันจะไม่ขยับ และคำสั่งใหม่จะไม่มี

**3. วาง `Setup.gs` แต่ลืม `Config.gs`**
ชื่อแท็บใหม่จะเป็น `undefined` แล้ว `insertSheet(undefined)` **ไม่ error**
แต่สร้างแท็บชื่อ `Sheet1` ที่ถูกทุกอย่างยกเว้นชื่อ ซึ่งโค้ดหาไม่เจอตลอดไป
— ตอนนี้มีตัวดักไว้แล้วใน `createIfMissing_()` แต่ให้ระวังรูปแบบนี้กับกรณีอื่น

**4. กด Undo ในหน้าจอ Apps Script แล้วโค้ดย้อนกลับเงียบ ๆ**
เกิดขึ้นสองครั้งกับ `Config.gs` — หลังวางเสร็จให้กด Cmd+S แล้วอย่าแตะ Undo ต่อ

**5. แก้ Google Form แล้วหัวคอลัมน์ในชีตเลื่อน**
ทุกครั้งที่แก้ฟอร์ม Google จะเขียนหัวแถวใหม่ทับ และคอลัมน์ของคำถามใหม่จะถูกแทรก
**หลังคำถามสุดท้ายที่ยังมีอยู่** ดันคอลัมน์ที่ระบบสร้างเองไปทางขวา
→ Run `restoreFormHeaders()` ทุกครั้งหลังแก้ฟอร์ม

**6. `setupSheets()` ไม่อัปเดตหัวตารางของแท็บที่มีข้อมูลอยู่แล้ว**
มันเขียนหัวตารางเฉพาะแท็บที่ว่างเปล่าจริง ๆ ถ้าต้องเพิ่มคอลัมน์ในแท็บที่มีหัวตารางเดิม
ต้องลบแถวหัวทิ้งก่อน (เมื่อแท็บนั้นไม่มีข้อมูล) แล้วรันใหม่

**7. ไฟล์ CSV ที่ไม่มี BOM จะเปิดใน Excel แล้วภาษาไทยเพี้ยน**
เปิดใน Numbers หรือ Google Sheets จะดูปกติ ทำให้ไม่มีใครเจอจนกว่าจะมีคนใช้ Excel จริง
— ทุกที่ในระบบใช้ `src/lib/csv.ts` ซึ่งใส่ BOM ให้แล้ว **อย่าเขียน CSV เองที่อื่น**

## 10. กฎเหล็กเรื่องข้อมูล

### ห้ามเด็ดขาด

1. **ห้ามเก็บชื่อผู้ป่วย HN เลขบัตรประชาชน หรือวันเกิดแบบเต็ม** ที่ใดในระบบ
2. **ห้ามตั้ง Google Sheet เป็น "ทุกคนที่มีลิงก์"** — ต้องเป็น Restricted แชร์ทีละอีเมล
3. **ห้ามให้ service account เป็น Editor** บนไฟล์ข้อมูลผู้ป่วย
4. **ห้ามเอาข้อมูลผู้ป่วยไปไว้ในไฟล์ตารางเวร** เพราะเว็บเขียนไฟล์นั้นได้
5. **ห้ามส่งข้อมูลผู้ป่วยผ่าน LINE** (PDPA-003) — ส่งได้แค่ลิงก์ที่ต้องมี token
6. **ห้ามเปิด repo เป็น public**

### นโยบายเก็บข้อมูล (PDPA-005)

|---|---|---|

**สิ่งที่คิดว่าจะได้ใช้วิเคราะห์ในอนาคต ต้องใส่ตั้งแต่วันนี้ ไม่ใช่วันที่จะใช้**

บทเรียนนี้เกิดจริงมาแล้วสามครั้ง (`comorbidity`, `insurance_scheme`,
`advice_question_type`) — แต่ละครั้งคือข้อมูลของช่วงก่อนหน้าที่หายไปถาวร

## 11. เมื่อระบบมีปัญหา — ไล่ตรวจตามอาการ

### แพทย์ต้นทางส่งฟอร์มแล้วเคสไม่ขึ้นบน dashboard

1. เปิดชีต `referrals` ดูว่ามีแถวใหม่ไหม → ไม่มี = ฟอร์มไม่ได้ผูกกับชีตนี้
2. มีแถวแต่คอลัมน์ `referral_type` เป็นข้อความไทยยาว ๆ = แปลค่าไม่ได้
   → ข้อความตัวเลือกในฟอร์มถูกแก้จนไม่ตรงกับ `TYPE_FROM_FORM_LABEL` ใน `Config.gs`
3. Apps Script → บันทึกการดำเนินการ ดู error ของ `onFormSubmit`

### จองคิวไม่ได้ / ตอบคำปรึกษาแล้วขึ้นว่าติดต่อไม่สำเร็จ

1. เปิด `/exec` ในเบราว์เซอร์ → ไม่ตอบ = deployment มีปัญหา
2. ตอบแต่เลขเวอร์ชันเก่า = ลืม deploy เวอร์ชันใหม่
3. `BOOKING_API_TOKEN` สองฝั่งไม่ตรงกัน → ขึ้นว่า "token ไม่ถูกต้อง"
4. Run `diagnoseBooking()`

### เข้าระบบด้วย LINE ไม่ได้

ดูข้อความสีแดงบนหน้า login ก่อน มันบอกสาเหตุไว้แล้ว

| ข้อความ | สาเหตุ |
|---|---|
| ไม่ได้อยู่ในกลุ่มงาน | บอทไม่ได้อยู่ในกลุ่ม หรือ `LINE_TARGET_*` ไม่มี groupId → Run `testLineTargets()` |
| ตรวจสอบสิทธิ์ไม่สำเร็จ | Apps Script ยังไม่ deploy เวอร์ชันใหม่ |
| ติดต่อ LINE ไม่สำเร็จ | Channel ID/secret ผิด หรือ Callback URL ไม่ตรง |
| หน้าแดง 400 ของ LINE | Callback URL ไม่ตรงกับที่ตั้งใน LINE Developers |
| เข้าได้แค่บางคน | LINE Login channel ยังเป็น **Developing** ต้องเปลี่ยนเป็น Published |

⚠️ ระบบออกแบบให้ **ตรวจไม่ได้ = ไม่ให้ผ่าน** ถ้า Apps Script ล่ม ทุกคนจะเข้าด้วย LINE ไม่ได้
แต่ยังเข้าด้วยรหัสผ่านได้ — **อย่าลบบัญชีรหัสผ่านทิ้งทั้งหมด เก็บไว้เป็นทางสำรอง**

### ไม่มีข้อความแจ้งเตือนเข้ากลุ่ม LINE

1. Run `showLineConfigStatus()` — ดูว่าตั้งค่าครบไหม (ไม่ส่งข้อความ)
2. Run `testLineTargets()` — ส่งจริงเข้าทุกกลุ่ม
3. ตอบ 200 ไม่ได้แปลว่ามีคนเห็น ต้องไปเปิด LINE ดูจริง

### หน้าเว็บขึ้นว่า "กำลังแสดงข้อมูลตัวอย่าง"

Cloudflare อ่านชีตไม่ได้ — ตรวจ `GOOGLE_SHEET_ID`, `GOOGLE_PRIVATE_KEY`
และว่ายังแชร์ชีตให้ service account อยู่ไหม

### สถิติหายไปเฉย ๆ

น่าจะไม่หาย — ดูว่ามีการตั้งช่วงวันที่ค้างไว้ในหน้าสถิติหรือเปล่า กด **"ทั้งหมด"**
และถ้าเคสเก่ากว่า 12 เดือนหายไปจริง นั่นคือรอบถอดชื่อทำงานตามปกติ
ตัวเลขย้อนหลังอยู่ใน `advice_library` และ `stats_monthly`

## 12. บันทึกการตัดสินใจ — ทำไมถึงเป็นแบบนี้

ส่วนนี้มีค่าที่สุดสำหรับคนที่มารับช่วงต่อ เพราะโค้ดบอกได้ว่า *ทำอะไร*
แต่บอกไม่ได้ว่า *ทำไมไม่ทำอีกแบบ*

**แบ่งกลุ่มตามสิ่งที่ต้องการ ไม่ใช่ตามชื่อโรค**
เพราะแพทย์ต้นทางรู้ว่าตัวเองต้องการอะไร แต่ไม่จำเป็นต้องรู้ว่าเคสนี้ควรเข้าทางไหนของเรา

**กลุ่ม 1 จองคิวเอง ไม่ผ่านฟอร์ม** (มติ 2 ส.ค. 2569)
การนัดคือการเลือกช่องเวลาว่าง ไม่ใช่การส่งข้อมูลไปรอคนอ่าน

**กลุ่ม 4 ออกจากระบบ** (มติ 2 ส.ค. 2569)
ใช้ระบบนัดหมายของโรงพยาบาลที่มีอยู่แล้ว ไม่สร้างช่องทางซ้ำ

**SLA เป็น 3 วันทำการนับจากวันที่ส่ง** (มติ 29 ส.ค. 2569)
เดิม 48 ชั่วโมงทำการ = 6 วันทำงาน ซึ่งยาวกว่าที่ทุกคนเข้าใจถึงสี่เท่า
และตัวเลขเดียวนี้กลืนความล่าช้าจากรอบแจ้งเตือน 10:00 น. ไว้แล้ว ไม่ต้องมีสองเกณฑ์

**คำตอบต้องมีอาจารย์รับรองก่อนส่ง**
เป็นคำรับรองของ resident ไม่ใช่การอนุมัติที่ระบบพิสูจน์ได้ — เหมือนใบ consult กระดาษ
ที่ resident เซ็นชื่ออาจารย์กำกับ **รายงานที่อ้างคอลัมน์นี้ต้องเข้าใจข้อจำกัดนั้น**

**ไม่ให้ LINE ส่งต่อคำถามจิปาถะเข้าแอดมินอัตโนมัติ**
ลองแล้วสองรอบ ทั้งสองรอบสร้างภาระเดิมที่ระบบนี้ตั้งใจจะกำจัดกลับขึ้นมาใหม่
ปัจจุบันต้องพิมพ์คำว่า `admin` นำหน้าเท่านั้นถึงจะถึงแอดมิน

**ประเภทคำถามให้ resident เลือกตอนตอบ ไม่ใช่แพทย์ต้นทางเลือกตอนถาม**
คนที่อ่านคำถามจบแล้วรู้ว่าถามอะไรจริง ๆ ต่างจากคนถามที่ต้องการถาม ไม่ได้ต้องการจัดประเภท
และไม่ต้องแก้ Google Form ซึ่งทุกครั้งที่แก้จะทำให้หัวคอลัมน์เลื่อน

**กราฟวงกลมได้มากสุด 4 ชิ้น**
ลองหาสีที่ห้าแล้วห้าตัว ไม่มีตัวไหนแยกจากสี่สีเดิมได้ถึงเกณฑ์เมื่อตรวจทุกคู่
วงกลมห้าชิ้นจึงมีอย่างน้อยหนึ่งคู่ที่คนสายตาปกติแยกไม่ออก
— แย่กว่าการยุบเป็น "อื่น ๆ" ที่ยังบอกยอดรวมได้ตรงไปตรงมา

**ช่วงวันที่ในหน้าสถิติคุมทั้งหน้า ไม่ใช่แค่ไฟล์ที่โหลด**
ถ้าคุมแค่ไฟล์ วันหนึ่งจะมีสไลด์ที่กราฟเป็นทั้งปีแต่ตัวเลขใต้กราฟเป็นไตรมาสเดียว
โดยที่ตัวเลขทุกตัวถูกต้อง แต่สไลด์ผิด

**เข้าระบบด้วย LINE เพิ่มความรับผิดชอบ ไม่ได้ลด**
บัญชีรหัสผ่านใช้ร่วมกันในวอร์ด ระบบจึงตอบไม่ได้ว่าใครเปิดดูข้อมูลผู้ป่วย
LINE ระบุตัวคนได้ และทุกครั้งที่เข้าถูกบันทึกใน `dashboard_logins`
**รายการที่ถูกปฏิเสธสำคัญที่สุด** เพราะเป็นสัญญาณเดียวที่บอกว่ามีคนนอกพยายามเข้า
หรือมีคนของเราหลุดออกจากกลุ่มโดยไม่ตั้งใจ

## 14. แนวทางพัฒนาต่อ

### สิ่งที่วางรากไว้แล้วแต่ยังไม่ได้ใช้

**คลังคำตอบถาวร (`advice_library`) ถูกออกแบบมาเพื่อการวิเคราะห์ตั้งแต่ต้น**

เก็บครบทั้ง โจทย์ (กลุ่มโรค การวินิจฉัย ระยะ โรคร่วม สิทธิการรักษา การรักษาเดิม คำถาม)
และคำตอบ (เนื้อคำตอบ สูตรยาที่เลือก ประเภทคำถาม) โดยไม่มีข้อมูลที่ระบุตัวผู้ป่วย

เป็นชุดข้อมูลที่พร้อมสำหรับการวิเคราะห์หรือ machine learning ในอนาคต
**และเป็นองค์ความรู้ที่ HIS ไม่ได้เก็บ** — HIS รู้ว่าผู้ป่วยได้รับยาอะไร
แต่ไม่รู้ว่าทำไมถึงเลือกสูตรนั้นและใครเป็นคนแนะนำ

⚠️ ตอนนี้มีข้อมูลน้อยมาก คลังจะเริ่มมีประโยชน์ราว 50–100 เคสที่ตอบแล้ว

**`src/lib/similar-cases.ts`** เป็นการหาเคสคล้ายด้วยกฎ (ให้คะแนนตามกลุ่มโรค สิทธิ
คำในการวินิจฉัยและคำถาม) ทำงานได้ทันทีแม้มีเคสน้อย และเป็นที่ทางสำหรับต่อยอด
ไปเป็นการค้นด้วย embedding เมื่อข้อมูลมากพอ

### ถ้าจะทำ AI ช่วยค้นแนวทาง (RAG)

แนวทางที่คุยกันไว้ เรียงตามลำดับความเสี่ยงจากน้อยไปมาก

**ขั้นที่ 1 — ค้นอย่างเดียว ไม่ให้เขียนอะไรเลย** ← เริ่มตรงนี้
แสดงลิงก์ไปหน้าที่เกี่ยวข้องใน guideline บน Drive ข้างแผงเคสคล้ายที่มีอยู่แล้ว
คนอ่านต้นฉบับเอง ไม่มีข้อความที่ AI แต่งขึ้น ได้ประโยชน์ทันทีแม้คลังยังว่าง

**ขั้นที่ 2 — ถามตารางนัดด้วยภาษาพูด**
⚠️ AI แปลคำถามเป็นเงื่อนไข → **โค้ดเป็นคนนับ** → AI เรียบเรียงผลลัพธ์
ห้ามให้โมเดลอ่านแถวแล้วนับเอง เพราะมันจะตอบเลขผิดด้วยน้ำเสียงมั่นใจเท่าเดิม

**ขั้นที่ 3 — ร่างคำตอบ** ⚠️ ต้องผ่านความเห็นชอบของภาควิชาก่อน
ทั้งระบบตั้งอยู่บนกติกาว่าคำตอบต้องผ่านอาจารย์ ร่างจาก AI ที่ resident ที่กำลังรีบ
คัดลอก–วาง–ติ๊ก–ส่ง คือความล้มเหลวแบบเดียวกับที่ประตูบานนั้นสร้างมาเพื่อกัน
ถ้าทำ: ต้องอ้างอิงทุกประโยค · ห้ามเติมลงช่องคำตอบอัตโนมัติ · ประตูอาจารย์อยู่เหมือนเดิม

**ข้อควรระวังเชิงสถาปัตยกรรม**
- ⚠️ ห้ามให้ AI อ่านชีต `referrals` (มีชื่อ–เบอร์แพทย์ต้นทาง) ให้ใช้ `advice_library`
- ถ้าใช้เครื่องส่วนตัว ให้ทำงานหนักแบบ offline แล้วอัปเฉพาะผลลัพธ์ขึ้นไป
  **อย่าเอาระบบที่ต้องพึ่งพาได้ 100% ไปผูกกับเครื่องที่ต้องเปิดตลอดเวลา**
- ถ้าจำเป็นต้องเสิร์ฟจริง ให้กรองที่ Cloudflare ทุกชั้น (tunnel ไม่เปิดพอร์ต +
  service token + ต้องล็อกอินก่อน + จำกัดจำนวนครั้ง) ไม่ใช่กรองที่ปลายทาง
- embedding ต้องเลือกรุ่นที่รองรับภาษาไทยจริง และ**ทั้งสองฝั่งต้องใช้รุ่นเดียวกัน**
- ข้อมูลระดับนี้ยังไม่ต้องใช้ vector database — ไฟล์เวกเตอร์ธรรมดาเร็วพอและดูแลง่ายกว่า

## หลักการที่อยากให้รักษาไว้

ถ้าจำอะไรจากเอกสารนี้ได้อย่างเดียว ขอให้เป็นสามข้อนี้

**1. ระบบที่ล้มเหลวแบบเงียบ ๆ อันตรายกว่าระบบที่พังดัง ๆ**
โค้ดในโปรเจกต์นี้จึงมีตัวดักและข้อความเตือนอยู่เยอะ — `checkCodeFiles()`,
`previewRetention()`, การเตือนเมื่อ `undefined`, การบอกเลขเวอร์ชันในข้อความ error
สิ่งเหล่านี้ไม่ใช่ของฟุ่มเฟือย ทุกตัวเกิดจากปัญหาที่เคยเสียเวลาจริงมาแล้ว

**2. เก็บข้อมูลให้น้อยที่สุดเท่าที่ทำงานได้ แต่เก็บสิ่งที่จะได้ใช้วิเคราะห์ตั้งแต่วันแรก**
สองข้อนี้ไม่ขัดกัน — ข้อแรกคือห้ามเก็บสิ่งที่ระบุตัวคน ข้อสองคือห้ามผัดผ่อน
การเก็บตัวแปรที่ไม่ระบุตัวคนแต่จำเป็นต่อการเข้าใจภายหลัง

**3. ความสะดวกที่แลกมาด้วยความถูกต้องของข้อมูลผู้ป่วย ไม่ใช่ความสะดวก**
ทุกครั้งที่ต้องเลือก ให้เลือกทางที่ผิดแล้วรู้ตัว มากกว่าทางที่ผิดแล้วไม่มีใครรู้
