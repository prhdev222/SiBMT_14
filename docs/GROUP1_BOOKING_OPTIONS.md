# บันทึกขอความเห็น — การจัดคิวกลุ่มที่ 1 และช่องทางสื่อสาร

**เรื่อง** ขอมติเรื่องวิธีจัดคิว fellow transplant หลังแพทย์ต้นทางกรอกฟอร์ม
**เสนอ** อาจารย์ที่ปรึกษาโครงการ
**วันที่** 2 สิงหาคม 2569

---

## 1. เรื่องที่ขอมติ

ลำดับการใช้งานจริงที่วางไว้คือ

```
แจก LINE OA → แพทย์ต้นทางกดเมนู → กรอก Google Form → ข้อมูลลง Google Sheet → ??? → ผู้ป่วยได้วันนัด
```

**ช่องว่างอยู่ที่เครื่องหมายคำถาม** — จากข้อมูลที่ลงชีตแล้ว จะไปถึงวันนัดได้อย่างไร
ปัจจุบันกำหนดให้แพทย์แอดมินกลางเปิดดูแล้วจัดคิวให้ทุกเคสด้วยตนเอง

เอกสารนี้เสนอ **5 ทางเลือก** พร้อมข้อดีข้อเสีย ร่างข้อความสื่อสารทุกจังหวะ
และข้อจำกัดของ LINE ที่ต้องทราบก่อนตัดสินใจ

> **ข้อเสนอของผู้จัดทำ: แบบ E — ระบบจัดคิวให้อัตโนมัติเมื่อเอกสารครบ แล้วเปลี่ยนวันเองได้**
> แพทย์ต้นทางกรอกฟอร์มครั้งเดียวจบ ได้วันนัดพร้อมชื่อ fellow กลับไปทันที
> โดยยังกันเคสที่เอกสารไม่พร้อมไม่ให้ได้คิว

## 2. ปัญหาของขั้นตอนปัจจุบัน

```
ส่งฟอร์ม → [ รอแอดมินเปิดดู ] → แอดมินเลือกวัน+fellow → [ รอแอดมินแจ้งกลับ ] → ทราบวันนัด
                 ↑ คอขวด                                        ↑ คอขวด
```

- กำหนดเวลาตอบกลับของกลุ่มนี้คือ 48 ชั่วโมงทำการ — ยื่นเย็นวันศุกร์ ได้คำตอบวันอังคาร
- แอดมินหนึ่งท่านเป็นจุดเดียวที่ระบบพึ่งพา ลาหรือติดผ่าตัดแล้วงานค้างทั้งกอง
- งานที่แอดมินทำจริงส่วนใหญ่คือ "ดูว่าวันไหนว่าง แล้วพิมพ์ชื่อลงไป" ซึ่งระบบทำแทนได้

## 3. ข้อค้นพบสำคัญก่อนตัดสินใจ

**ขั้นตรวจสอบของกลุ่มที่ 1 ไม่ได้มีไว้เพราะระเบียบ แต่มีไว้กันผู้ป่วยเสียเที่ยว**

ระบบมีสถานะ `Incomplete` สำหรับกรณีเอกสารไม่ครบ (เช่น ผล chromosome หรือ molecular ยังไม่ออก)
หากปล่อยให้ได้คิวทันทีโดยไม่ตรวจอะไรเลย จะเกิดกรณี

> ผู้ป่วยจากต่างจังหวัดเดินทางมาถึง OPD 700 ตามนัด แล้วประเมินต่อไม่ได้เพราะผลยังไม่ครบ
> เสียทั้งค่าเดินทาง เสียคิว fellow และต้องนัดใหม่

**คำถามที่ถูกต้องจึงไม่ใช่ "มีแอดมินหรือไม่มี" แต่คือ**

| คำถาม | คำตอบ |
| --- | --- |
| อะไรที่ **ระบบตรวจแทนได้** | ความครบถ้วนของเอกสาร (ฟอร์มถามอยู่แล้วในช่อง `documents_ready`) และคิวว่างของ fellow |
| อะไรที่ **ต้องใช้วิจารณญาณแพทย์** | เคสที่ไม่ควรเข้าคลินิกปลูกถ่ายตั้งแต่ต้น, ข้อมูลย้อนแย้ง, เคสเร่งด่วนพิเศษ |

## 4. ทางเลือกทั้งห้า

### แบบ A — คงเดิม: แอดมินจัดคิวทุกเคส

```
ส่งฟอร์ม → แอดมินตรวจ → แอดมินเลือกวัน+fellow → แจ้งกลับ
```

ทุกเคสผ่านสายตาแพทย์ก่อนเสมอ ควบคุมคุณภาพได้เต็มที่
แต่คอขวดอยู่ที่คนเดียว ภาระงานไม่ลด และผู้ป่วยรอนานที่สุด

---

### แบบ B — จองเองได้ทุกเคส ไม่มีการตรวจ

```
ส่งฟอร์ม → ได้ลิงก์จองทันที → เลือกวันเอง → ยืนยัน
```

เร็วที่สุดและแอดมินแทบไม่ต้องทำอะไร แต่**เคสเอกสารไม่ครบก็จองคิวได้**
ไม่แนะนำสำหรับกลุ่มที่ 1 เพราะเป็นกลุ่มที่ต้องเตรียมเอกสารมากที่สุดในสี่กลุ่ม

---

### แบบ C — จองเองได้เมื่อเอกสารครบ

```
ส่งฟอร์ม → ระบบตรวจเอกสาร → ครบ: ส่งลิงก์ให้เลือกวันเอง
                            → ไม่ครบ: แจ้งว่าขาดอะไร แล้วเข้าคิวแอดมิน
```

เคสส่วนใหญ่ไม่ต้องรอคน แอดมินเหลือแต่งานที่ต้องใช้วิจารณญาณ
ข้อเสียคือแพทย์ต้นทางต้อง**ทำสองจังหวะ** — กรอกฟอร์มแล้วยังต้องกลับมากดเลือกวันอีกครั้ง

---

### แบบ D — แยกเงื่อนไขตามกลุ่มโรค

เช่น Acute Leukemia ให้จองเองได้ทันที ส่วน MDS / MPN ต้องให้แพทย์อนุมัติก่อน

ละเอียดตรงกับความเป็นจริงทางคลินิกที่สุด แต่กติกาซับซ้อน อธิบายให้แพทย์ต้นทางเข้าใจยาก
และต้องมีคนคอยทบทวนว่ากลุ่มโรคใดควรอยู่ฝั่งใด

---

### แบบ E — ระบบจัดคิวให้อัตโนมัติ แล้วเปลี่ยนวันเองได้ ⬅️ **ข้อเสนอ**

```
ส่งฟอร์ม (ระบุช่วงเวลาที่สะดวกอยู่แล้วในฟอร์ม)
   ↓
ระบบตรวจเอกสารอัตโนมัติ
   ↓
├── ครบ    → ระบบเลือกวันว่างวันแรกที่ตรงกับช่วงที่ระบุ
│            + เลือก fellow ที่คิวเหลือมากที่สุด (เกลี่ยงานอัตโนมัติ)
│            → ส่งข้อความยืนยันเต็มรูปแบบทันที พร้อมลิงก์ "เปลี่ยนวัน"
│
└── ไม่ครบ → แจ้งว่าขาดเอกสารอะไร + เข้าคิวให้ resident/แอดมินติดตาม
```

**จุดต่างจากแบบ C** — แพทย์ต้นทาง**ไม่ต้องกลับมาทำอะไรอีก** กรอกฟอร์มครั้งเดียวได้วันนัดเลย
ส่วนคนที่วันนัดไม่สะดวกค่อยกดลิงก์เปลี่ยน ซึ่งเป็นคนส่วนน้อย

**ฟอร์มมีช่อง "ช่วงเวลาที่สะดวกให้ผู้ป่วยมาตรวจ" อยู่แล้ว** จึงใช้ข้อมูลเดิม ไม่ต้องเพิ่มคำถาม

**การเลือก fellow** — ระบบเลือกท่านที่มีคิวเหลือมากที่สุดในวันนั้น
ตรงกับเจตนาเดิมของโครงการที่ต้องการเกลี่ยงานให้สมดุล ไม่ให้กระจุกที่คนใดคนหนึ่ง

---

## 5. ช่องทางสื่อสาร — แจ้งครบสามทาง

**หลักการ: แจ้งทาง LINE เป็นหลัก อีเมลเป็นสำรอง และเปิดดูบนเว็บได้ตลอดเวลา**

แพทย์ในไทยส่วนใหญ่ใช้ LINE เป็นช่องทางหลักและไม่ค่อยเปิดอีเมลของตนเอง
การแจ้งทางอีเมลอย่างเดียวจึงมีความเสี่ยงสูงที่จะ**ส่งไปแล้วไม่มีใครอ่าน**
ระบบจึงควรแจ้งทุกช่องทางที่มี เพราะแพทย์แต่ละท่านมีนิสัยการใช้งานต่างกัน

| ช่องทาง | บทบาท | ผู้ป่วยจะพลาดข้อมูลไหม |
| --- | --- | --- |
| **LINE** | ช่องทางหลัก แจ้งทันทีและแพทย์เปิดอ่านแน่นอน | น้อยที่สุด |
| **อีเมล** | สำรอง เก็บเป็นหลักฐานได้ พิมพ์ออกมาแนบแฟ้มได้ | ปานกลาง |
| **หน้าเว็บสถานะเคส** | ลิงก์ถาวรประจำเคส เปิดดูเมื่อไหร่ก็ได้ ไม่ต้องค้นย้อนหลัง | — |

### ข้อจำกัดทางเทคนิคที่ต้องแก้ก่อน

LINE Official Account จะส่งข้อความหาใครได้ ต้องครบสองเงื่อนไข

1. คนนั้นเพิ่ม OA เป็นเพื่อนแล้ว — **ผ่าน** เพราะเราแจก LINE OA เป็นทางเข้า
2. ระบบรู้ว่า LINE บัญชีไหนคือเคสไหน — **ต้องทำเพิ่ม**

เมื่อแพทย์กดเมนูใน LINE แล้วไปกรอก Google Form ระบบได้ข้อมูลจากฟอร์ม
แต่ไม่รู้ว่าคนกรอกคือบัญชี LINE ใด เพราะเป็นคนละระบบกัน

### วิธีแก้ที่เสนอ — ให้เมนู LINE พาไปหน้าที่รู้จักผู้ใช้

เปลี่ยนปุ่มใน Rich Menu จาก "เปิดเว็บธรรมดา" เป็น **LIFF**
ซึ่งเป็นหน้าเว็บที่เปิดในแอป LINE และทราบว่าผู้กดคือบัญชีใดโดยอัตโนมัติ

```
แพทย์กดเมนูใน LINE
   ↓
หน้า LIFF (รู้บัญชี LINE ของผู้กดทันที ผู้ใช้ไม่ต้องทำอะไรเพิ่ม)
   ↓
กดเลือกกลุ่ม → เปิด Google Form ที่เติมรหัสบัญชี LINE ไว้ให้แล้ว
   ↓
ส่งฟอร์ม → ชีตได้ทั้งข้อมูลเคสและรหัสบัญชี LINE
   ↓
ระบบแจ้งกลับได้ทั้ง LINE + อีเมล + ลิงก์หน้าเว็บ
```

**สิ่งที่ต้องทำเพิ่ม**

- สร้าง LINE Login channel เพิ่มอีกหนึ่งช่อง **ภายใต้ Provider เดียวกับ Messaging API**
  (ข้อนี้สำคัญ — ถ้าอยู่คนละ Provider รหัสผู้ใช้จะไม่ตรงกันและส่งข้อความไม่ได้)
- สร้าง LIFF app ชี้มาที่หน้าเว็บของระบบ
- เพิ่มคำถามหนึ่งข้อในฟอร์มชื่อ `line_user_id` สำหรับรับรหัสบัญชีที่เติมมาให้อัตโนมัติ

**ประเมินว่าเป็นงานไม่มาก และควรทำตั้งแต่ระยะแรก** ไม่ใช่ทิ้งไว้ทีหลัง
เพราะถ้าเริ่มใช้ด้วยอีเมลอย่างเดียวไปก่อน จะเกิดเคสที่แจ้งวันนัดไปแล้วไม่มีใครอ่าน

> **กรณีสำรอง** — หากแพทย์กรอกฟอร์มจากลิงก์ที่ส่งต่อกันมา (ไม่ได้ผ่านเมนู LINE)
> ระบบจะไม่มีรหัสบัญชี LINE จึงแจ้งทางอีเมลและลิงก์หน้าเว็บแทน
> และในข้อความจะบอกวิธีผูกบัญชี LINE ไว้ให้ด้วย

### สรุปผู้รับแต่ละกลุ่ม

| ผู้รับ | ช่องทาง |
| --- | --- |
| **แพทย์ต้นทาง** | **LINE** (หลัก) + **อีเมล** (สำรอง) + **หน้าเว็บสถานะเคส** |
| แพทย์ประจำบ้านวอร์ดเคโม | LINE กลุ่ม + dashboard |
| แพทย์แอดมินกลาง | LINE กลุ่ม/ส่วนตัว + dashboard |
| fellow transplant | LINE กลุ่ม + dashboard (เห็นคิวและ checklist ล่วงหน้า) |

## 6. ร่างข้อความสื่อสาร (ตามแบบ E)

**ทุกจังหวะส่งทั้ง LINE และอีเมล** เนื้อหาเดียวกันแต่รูปแบบต่างกัน
— LINE สั้นกระชับอ่านบนมือถือ / อีเมลละเอียดครบถ้วนพิมพ์เก็บได้

### จังหวะที่ 1ก — เอกสารครบ: ยืนยันนัดทันที (ข้อความ LINE)

```
✅ ยืนยันนัดเรียบร้อย
HEM-20260802-0001

📅 จันทร์ที่ 10 ส.ค. 2569  เวลา 08:00 น.
📍 OPD 700 โรงพยาบาลศิริราช
👨‍⚕️ พบ พญ. ณัฐกานต์ (fellow transplant)

⚠️ กรุณาเขียนบนหัวใบ refer ว่า
"ส่งพบ fellow transplant ชื่อ พญ. ณัฐกานต์ ที่ OPD 700"
เพื่อให้พยาบาลคัดกรองส่งผู้ป่วยถึงตัวแพทย์ได้ทันที

⚠️ แจ้งผู้ป่วยทำบัตรโรงพยาบาลก่อนวันนัด

📄 รายละเอียด เอกสารที่ต้องเตรียม และเปลี่ยนวันนัด
<ลิงก์หน้าเว็บสถานะเคส>

🔒 อย่าพิมพ์ชื่อ-สกุลหรือเลข HN ในแชทนี้
```

> ข้อความ LINE ตั้งใจให้สั้น ใส่เฉพาะสิ่งที่ต้องทำทันที
> ส่วนรายละเอียดยาว ๆ อยู่ในลิงก์หน้าเว็บและอีเมล

### หน้าเว็บสถานะเคส (ลิงก์ถาวรประจำเคส)

## 7. Google Sheet — ใครเห็นอะไร และระบบเขียนอะไรบ้าง

ระบบใช้ Google Sheet **สองไฟล์แยกกันโดยเจตนา** เพื่อจำกัดสิทธิ์การเขียน

**เหตุผลที่แยก** — สิทธิ์ของ Google Sheets กำหนดได้เป็นรายไฟล์เท่านั้น กำหนดรายแท็บไม่ได้
หากตารางเวรอยู่ไฟล์เดียวกับข้อมูลผู้ป่วย การให้เว็บเขียนตารางเวรได้

| คอลัมน์ | ค่า |
| --- | --- |

## 11. ประเด็นที่ขอมติจากอาจารย์

1. **เลือกแนวทางใด** — A (คงเดิม) / B (จองเสรี) / C (จองเองเมื่อครบ) / **E (ระบบจัดให้)** / D (แยกตามโรค)

2. **เอกสารอะไรบ้างที่ถือว่า "ครบ" จนได้คิว**
   ขอรายการที่ชัดเจน เพื่อตั้งเป็นเงื่อนไขในระบบ
   (ฟอร์มถามไว้แล้วแต่ยังไม่ได้กำหนดว่าข้อใดบังคับ)

3. **ยอมรับให้ระบบเลือก fellow แทนคนได้หรือไม่**
   ระบบจะเลือกท่านที่คิวเหลือมากที่สุดเพื่อเกลี่ยงาน
   หรืออาจารย์ประสงค์ให้ผู้ป่วยบางลักษณะพบ fellow ท่านใดท่านหนึ่งเป็นการเฉพาะ

4. **ระยะเวลาที่ให้เปลี่ยน/ยกเลิกนัดเองได้** — เสนอไว้ที่ 3 วันก่อนวันนัด

5. **เปิดให้จองล่วงหน้าได้ไกลแค่ไหน** — เสนอไว้ที่ 8 สัปดาห์

6. **ผู้รับผิดชอบเมื่อผู้ป่วยมาแล้วประเมินต่อไม่ได้เพราะเอกสารไม่ครบ**
   ควรมีข้อตกลงชัดเจนก่อนเปิดใช้ เพราะเป็นการย้ายความรับผิดชอบ
   ส่วนหนึ่งไปที่แพทย์ต้นทาง

7. **เห็นชอบให้แจ้งครบสามช่องทาง (LINE + อีเมล + หน้าเว็บ) หรือไม่**
   และเห็นชอบให้ทำการเชื่อม LINE (LIFF) **ตั้งแต่ระยะแรก** หรือไม่
   — จำเป็นเพราะแพทย์ส่วนใหญ่ไม่เปิดอีเมล การส่งอีเมลอย่างเดียวเสี่ยงไม่มีใครอ่าน
   พร้อมกับตั้งช่องอีเมลในฟอร์มเป็นข้อบังคับไว้เป็นหลักประกันขั้นต่ำ

8. **ชื่อผู้สำรองของแพทย์แอดมินกลาง** — ยังไม่ได้รับข้อมูล (ค้างจากบันทึกครั้งก่อน)

- ระบบล็อกอินด้วยรหัสผ่านรายบุคคล ไม่ต้องใช้อีเมล
- แยกไฟล์ Google Sheet ตารางเวรออกจากไฟล์ข้อมูลผู้ป่วย
- ระบบส่งอีเมลแจ้งเลข referral ID ถึงแพทย์ต้นทางอัตโนมัติ

**รอมติจากเอกสารฉบับนี้**

- กลไกจัดคิวอัตโนมัติ และหน้าจอเปลี่ยน/ยกเลิกนัดสำหรับแพทย์ต้นทาง
- ข้อความสื่อสารทั้งสามจังหวะ
- การตั้งช่องอีเมลในฟอร์มเป็นข้อบังคับ

**ยังไม่ได้เริ่ม**

- LINE Official Account, Rich Menu และข้อความตอบกลับอัตโนมัติ
- การเชื่อม LINE ให้ส่งข้อความถึงแพทย์ต้นทางรายบุคคลได้ (LINE Login + LIFF)
- หน้าเว็บสถานะเคสสำหรับแพทย์ต้นทาง
