# คู่มือติดตั้ง — สร้าง Google Form และ Google Sheet ทีละขั้น

คู่มือนี้เป็น **ขั้นตอนคลิกจริง** สำหรับคนที่ลงมือสร้าง
ส่วนรายละเอียดว่าฟอร์มมีคำถามอะไรบ้างอยู่ที่ [FORMS_AND_SHEETS.md](FORMS_AND_SHEETS.md)

**เวลาที่ใช้โดยประมาณ:** 2–3 ชั่วโมง (ส่วนใหญ่หมดไปกับการพิมพ์คำถามลงฟอร์ม)

**ลำดับสำคัญ — ห้ามสลับ** เพราะขั้นหลัง ๆ ต้องใช้ผลจากขั้นก่อน

| ขั้น | ทำอะไร | ใช้เวลา |
| --- | --- | --- |
| 1 | สร้างฟอร์มเปล่าและตั้งค่าพื้นฐาน | 10 นาที |
| 2 | สร้าง section ทั้ง 7 ให้ครบก่อน | 10 นาที |
| 3 | ใส่คำถามและตั้ง branching | 60–90 นาที |
| 4 | เชื่อมกับ Google Sheet และเปลี่ยนชื่อหัวคอลัมน์ | 20 นาที |
| 5 | ติดตั้ง Apps Script | 20 นาที |
| 6 | สร้างลิงก์ prefilled 4 อัน | 10 นาที |
| 7 | สร้าง service account ให้ dashboard อ่านชีตได้ | 20 นาที |
| 8 | ทดสอบทั้งระบบ | 20 นาที |

## ขั้นที่ 1 — สร้างฟอร์มและตั้งค่าพื้นฐาน

1. เปิด [forms.google.com](https://forms.google.com) → กด **Blank form**
2. ตั้งชื่อฟอร์ม: `ระบบส่งต่อผู้ป่วยนอก สาขาวิชาโลหิตวิทยา ศิริราช`
3. กดไอคอน **⚙️ Settings** ด้านบน แล้วตั้งค่าดังนี้

| หัวข้อ | ตั้งเป็น | เหตุผล |
| --- | --- | --- |
| Collect email addresses | **ปิด** | อีเมลเป็นข้อมูลส่วนบุคคลที่ไม่จำเป็น เรามีเบอร์ติดต่อกลับอยู่แล้ว |
| Limit to 1 response | **ปิด** | แพทย์คนเดียวส่งได้หลายเคส |
| Allow response editing | **เปิด** | ให้แก้ไขเพิ่มข้อมูลได้เมื่อทีมขอเอกสารเพิ่ม |
| Show progress bar | **เปิด** | ฟอร์มมี 3–4 หน้า ควรให้ผู้กรอกเห็นว่าเหลืออีกเท่าไร |
| Shuffle question order | **ปิด** | — |

### 1.1 ตั้งข้อความที่ผู้กรอกเห็นหลังกดส่ง (Confirmation message)

คือข้อความที่ขึ้นบนหน้าจอ**หลังผู้กรอกกดส่งฟอร์ม** ค่าเริ่มต้นของ Google คือ
*"Your response has been recorded."* ซึ่งไม่บอกว่าจะได้รับการติดต่อกลับเมื่อไหร่

**วิธีตั้ง:** ⚙️ Settings → กดขยายหัวข้อ **Presentation** → ช่อง **Confirmation message**
→ กด **Edit** → วางข้อความนี้

```text
ได้รับข้อมูลเรียบร้อยแล้วค่ะ ขอบคุณค่ะ 🙏

ทีมงานจะรับเรื่องในรอบประจำวันเวลา 10:00 น. ของวันทำการ
และตอบกลับไปยังเบอร์ที่ท่านให้ไว้ภายใน 48 ชั่วโมงทำการ

📌 สำหรับกลุ่มที่ 4 (Refer ผู้ป่วยนอกทั่วไป)
ให้ผู้ป่วยสแกน QR code ระบบนัดหมายกลางของโรงพยาบาลศิริราช
เพื่อทำนัดกับแผนกผู้ป่วยนอกโดยตรง จะได้รับใบนัดภายใน 3 วันทำการ
หากผู้ป่วยไม่มีสมาร์ทโฟนหรือใช้ LINE ไม่ได้ กรุณาให้ติดต่อ 02-419-9903

⚠️ ระบบนี้ไม่ใช่ช่องทางฉุกเฉิน
หากผู้ป่วยมีภาวะฉุกเฉิน กรุณาใช้ช่องทางส่งต่อฉุกเฉินระหว่างโรงพยาบาลตามปกติ
```

> **ข้อจำกัดของ Google Form:** ข้อความนี้เป็นข้อความคงที่ **ใส่ Referral ID ไม่ได้**
> เพราะรหัสถูกสร้างโดย Apps Script หลังฟอร์มถูกส่งไปแล้ว — ดูวิธีแก้ในหัวข้อ 1.2

### 1.2 การส่ง Referral ID กลับให้แพทย์ผู้ส่ง

แพทย์ผู้ส่งควรรู้รหัสอ้างอิงของตัวเอง เพื่อใช้ตอนส่งข้อมูลเพิ่มหรือสอบถามความคืบหน้า
แต่ Confirmation message แสดงรหัสไม่ได้ตามที่อธิบายข้างต้น

**Apps Script จัดการให้แล้ว** — ระบบส่งอีเมลแจ้งรหัสอ้างอิงกลับไปอัตโนมัติ
ทันทีหลังส่งฟอร์ม ไปที่ช่อง `อีเมล` ในฟอร์ม (ข้อ 2.4 ซึ่ง**บังคับกรอก**)
(ฟังก์ชัน `sendReferralIdEmail_` ใน `OnFormSubmit.gs`)

อีเมลฉบับนี้มีเพียง **รหัสอ้างอิงและกลุ่มงาน ไม่มีข้อมูลผู้ป่วยใด ๆ**

รหัสนี้ยังใช้พิมพ์ถามสถานะกับบอท LINE ได้ด้วย (ดู [LINE_TEMPLATES.md](LINE_TEMPLATES.md) §3.4)
จึงไม่ใช่แค่เลขอ้างอิง แต่เป็นกุญแจเข้าช่องทางติดตามผลทั้งหมดของแพทย์ต้นทาง

ถ้าเจอเคสที่ไม่มีอีเมล (ฟอร์มรุ่นเก่า หรือแก้ฟอร์มพลาดจน Required หลุด)
ระบบจะเขียนเตือนไว้ใน Execution log ว่าเคสไหน แล้วต้องโทรแจ้งรหัสเอง

> **ข้อควรทราบ:** อีเมลส่งจากบัญชี Google ที่เป็นเจ้าของ Apps Script
> โควตาการส่งของบัญชี Workspace อยู่ที่ประมาณ 1,500 ฉบับ/วัน ซึ่งเกินพอสำหรับปริมาณนี้มาก
> ในข้อความจึงควรระบุชื่อหน่วยงานให้ชัด เพื่อไม่ให้ผู้รับเข้าใจผิดว่าเป็นอีเมลส่วนตัว

## ขั้นที่ 2 — สร้าง section ให้ครบ 7 อันก่อน

> **ทำขั้นนี้ให้เสร็จก่อนใส่คำถาม** เพราะ Google Form จะให้เลือกปลายทาง branching
> ได้เฉพาะ section ที่ **มีอยู่แล้ว** เท่านั้น ถ้าสร้างไม่ครบจะตั้ง branching ไม่ได้

กดปุ่ม **Add section** (ไอคอนสี่เหลี่ยมสองอันซ้อนกัน ทางขวามือ) รวม **6 ครั้ง**
จะได้ครบ 7 section

### ⚠️ Section 1 ต่างจากอันอื่น

**Section 1 ไม่มีช่องชื่อ section แยก** — มันใช้ **ชื่อฟอร์ม** และ **Form description**
ที่อยู่บนสุดแทน (ชื่อฟอร์มตั้งไว้แล้วตั้งแต่ขั้นที่ 1)

ส่วน Section 2–7 จะขึ้นว่า `Untitled Section` ให้กดแก้ชื่อได้ตามปกติ

| Section | ตั้งชื่ออย่างไร |
| --- | --- |
| 1 | **ไม่ต้องตั้งชื่อ section** — ใช้ชื่อฟอร์มที่มีอยู่ แล้ววางข้อความคำนำลงใน **Form description** (ดูข้อความในหัวข้อ 3.1) |
| 2 | แก้ `Untitled Section` → `ข้อมูลผู้ส่งและผู้ป่วย` |
| 3 | แก้ `Untitled Section` → `เลือกเรื่องที่ต้องการติดต่อ` |
| 4 | แก้ `Untitled Section` → `กลุ่มที่ 1 — ขอนัดพบแพทย์ปลูกถ่ายเซลล์ต้นกำเนิด` |
| 5 | แก้ `Untitled Section` → `กลุ่มที่ 2 — ขอความเห็นสูตรยาเคมีบำบัด` |
| 6 | แก้ `Untitled Section` → `กลุ่มที่ 3 — ขอส่งตัวมาให้ยาเคมีบำบัด/ยากดภูมิ` |
| 7 | แก้ `Untitled Section` → `กลุ่มที่ 4 — Refer ผู้ป่วยนอกด้วยเหตุผลอื่น` |

ตอนนี้ทุก section จะขึ้นว่า `After section N → Continue to next section` เหมือนกันหมด
**ยังไม่ต้องแก้** จะไปตั้ง branching ในขั้นที่ 3.3 และ 3.4

## ขั้นที่ 3 — ใส่คำถามและตั้ง branching

ใส่คำถามตาม [FORMS_AND_SHEETS.md](FORMS_AND_SHEETS.md) §2–§8
ทีละ section โดยมีจุดที่ต้องระวังดังนี้

### 3.0 วิธีเพิ่มคำถาม และข้อควรระวังเรื่องการคัดลอก

**วิธีเพิ่มคำถามให้ลงถูก section**

1. **คลิกที่การ์ดของ section นั้นก่อน** เพื่อให้การ์ดถูกเลือก
2. แถบเครื่องมือลอยจะเลื่อนมาอยู่ข้าง ๆ การ์ดที่เลือก
3. กด **⊕** (ไอคอนบนสุด) — คำถามใหม่จะแทรกต่อจากการ์ดที่เลือก

ถ้าไม่คลิกการ์ดก่อน คำถามอาจไปโผล่ผิด section
ให้ตรวจเสมอว่าคำถามใหม่อยู่ใต้หัว `Section N of 7` ที่ถูกต้อง

**⚠️ ห้ามคัดลอกทั้งแถวของตารางจากเอกสารมาวาง**

ตารางในเอกสารมีหลายคอลัมน์เพื่ออธิบาย เช่น

```
| กลุ่มที่ 4 — Refer ผู้ป่วยนอกด้วยเหตุผลอื่น | Section 7 | `GENERAL_OPD` |
```

สิ่งที่ต้องพิมพ์ลงฟอร์มคือ **เฉพาะคอลัมน์แรก** เท่านั้น

```
กลุ่มที่ 4 — Refer ผู้ป่วยนอกด้วยเหตุผลอื่น
```

คอลัมน์อื่นมีความหมายดังนี้ **ไม่ต้องพิมพ์ที่ไหนทั้งสิ้น**

| คอลัมน์ในเอกสาร | ความหมาย |
| --- | --- |
| `Section 7` | ปลายทาง branching — ไปเลือกใน dropdown ขั้นที่ 3.3 |
| `GENERAL_OPD` | ค่าที่ Apps Script แปลงให้เองเบื้องหลัง |
| `disease_group`, `diagnosis` ฯลฯ | ชื่อหัวคอลัมน์ในชีต — ไปเปลี่ยนในขั้นที่ 4.2 |

**เหตุผลที่ต้องเป๊ะ:** Apps Script เทียบข้อความตัวเลือกแบบตรงตัวอักษร
ถ้ามีส่วนเกินติดมา `referral_type` จะแปลงไม่สำเร็จ
และ **dashboard จะไม่แสดงเคสนั้นเลย** เพราะกรองแถวที่แปลงค่าไม่ได้ทิ้ง

### 3.1 Section 1 — คำนำและช่องรับทราบ

**ก. วางข้อความคำนำลงใน Form description**

คลิกที่ช่อง `Form description` ใต้ชื่อฟอร์ม แล้ววางข้อความนี้

```text
แบบฟอร์มนี้ใช้สำหรับผู้ป่วยนอกเท่านั้น ไม่ใช่ช่องทางฉุกเฉิน
หากผู้ป่วยมีภาวะฉุกเฉิน กรุณาใช้ช่องทางส่งต่อฉุกเฉินระหว่างโรงพยาบาลตามปกติ

ทีมงานจะรับเรื่องในรอบประจำวันเวลา 10:00 น. ของทุกวันทำการ
และตอบกลับภายใน 48 ชั่วโมงทำการ

⚠️ กรุณาอย่ากรอกชื่อ-สกุล เลข HN หรือเลขบัตรประชาชนของผู้ป่วยในแบบฟอร์มนี้
ระบบออกแบบให้ไม่เก็บข้อมูลระบุตัวตน เพื่อความปลอดภัยของผู้ป่วย
การติดต่อกลับจะทำผ่านแพทย์ผู้ส่งตัวโดยใช้รหัสอ้างอิงที่ระบบสร้างให้
```

**ข. เพิ่มคำถามช่องรับทราบ** (กดปุ่ม ⊕ เพื่อเพิ่มคำถามใน Section 1)

- ชื่อคำถาม: `การรับทราบก่อนส่งข้อมูล`
- ประเภทคำถาม: **Checkboxes**
- ตัวเลือก 3 ข้อ: คัดลอกจาก [FORMS_AND_SHEETS.md](FORMS_AND_SHEETS.md) §2
- เปิด **Required**
- กด **⋮ → Response validation** → เลือก **Select at least** → ใส่ `3`
- ข้อความแจ้งเตือน: `ต้องยืนยันครบทุกข้อจึงจะส่งแบบฟอร์มได้`

> ขั้นนี้สำคัญที่สุดในเชิงกฎหมาย เพราะมติของอาจารย์ให้ใช้ช่องรับทราบนี้
> แทนการขอรับรองจากฝ่ายสารสนเทศ

### 3.2 Section 2 — ข้อมูลร่วม

**ก. เพิ่มคำถาม 7 ข้อ**

เลื่อนไปที่ Section 2 กดปุ่ม **⊕** (เพิ่มคำถาม) แล้วใส่ทีละข้อตามนี้

พิมพ์ชื่อคำถามตามช่อง "ชื่อคำถาม" ให้ตรงตัว
ส่วนช่อง "Required" คือสถานะของ**สวิตช์ Required** ที่มุมขวาล่างของการ์ดคำถาม

| # | ชื่อคำถาม (พิมพ์ตามนี้) | ประเภท | สวิตช์ Required |
| --- | --- | --- | --- |
| 2.1 | `โรงพยาบาลต้นทาง` | Short answer | **เปิด** |
| 2.2 | `ชื่อแพทย์ผู้ส่งตัว` | Short answer | **เปิด** |
| 2.3 | `เบอร์ติดต่อกลับ` | Short answer | **เปิด** |
| 2.4 | `อีเมล` | Short answer | **เปิด** |
| 2.5 | `อายุผู้ป่วย (ปี)` | Short answer | **เปิด** |
| 2.6 | `เพศ` | Multiple choice → `ชาย` / `หญิง` | **เปิด** |
| 2.7 | `ความเร่งด่วน` | Multiple choice → `ปกติ` / `เร่งด่วน` | **เปิด** |

**การเปลี่ยนประเภทคำถาม:** กดที่ dropdown ด้านขวาของช่องชื่อคำถาม
(ค่าเริ่มต้นคือ `Multiple choice`) แล้วเลือก `Short answer`

**การเปิด/ปิด Required:** สวิตช์อยู่มุมขวาล่างของการ์ดคำถาม

**ข้อ 2.4 อีเมล — ทำไมถึงบังคับ**

เป็นอีเมลของ**แพทย์ผู้ส่ง** ไม่ใช่ของผู้ป่วย
ระบบส่ง **Referral ID** กลับไปให้ทันทีหลังส่งฟอร์ม เพราะหน้าจอ "ส่งสำเร็จ"
ของ Google Form แสดงรหัสไม่ได้ (รหัสถูกสร้างหลังจากนั้น)

> **เปลี่ยนเป็นบังคับเมื่อ 22 ส.ค. 2569** — เดิมเป็น "ไม่บังคับ เพราะแพทย์บางท่าน
> สะดวกรับทางโทรศัพท์มากกว่า" แต่ในทางปฏิบัติ เว้นว่างแล้วแพทย์จะไม่รู้รหัสอ้างอิงเลย
> เคสนั้นก็เงียบหายจนต้องโทรตามกันเอง และรหัสนั้นยังเป็นสิ่งที่ใช้พิมพ์ถามสถานะ
> กับบอท LINE ได้ด้วย (ดู LINE_TEMPLATES.md §3.4) ไม่มีรหัส = ใช้ช่องทางนั้นไม่ได้

ควรเพิ่มคำอธิบายใต้ชื่อคำถามด้วย: กด **⋮ → Description** แล้วพิมพ์

```text
อีเมลของแพทย์ผู้ส่ง — ระบบจะส่งรหัสอ้างอิงของเคสนี้กลับไปให้ทางอีเมลนี้
กรุณาตรวจว่าพิมพ์ถูกต้อง เพราะเป็นช่องทางเดียวที่จะได้รับรหัส
```

**ข. ใส่ Response validation (3 ช่อง)**

### 4.1 เชื่อมฟอร์มกับชีต

### 4.2 เปลี่ยนชื่อหัวคอลัมน์ (⚠️ ขั้นที่สำคัญที่สุด)

**ปัญหา:** Google Form เขียนหัวคอลัมน์เป็น **ข้อความคำถามภาษาไทย** เช่น `โรงพยาบาลต้นทาง`

**วิธีแก้:** แก้แถวที่ 1 ในชีต `referrals` ด้วยมือ ให้เป็นชื่อตามตารางนี้

| คอลัมน์ | เดิม (ข้อความคำถาม) | เปลี่ยนเป็น |
| --- | --- | --- |
| A | Timestamp | `submitted_at` |
| B | (ช่องรับทราบ) | `consent_raw` |
| C | โรงพยาบาลต้นทาง | `referrer_org` |
| D | ชื่อแพทย์ผู้ส่งตัว | `referrer_name` |
| E | เบอร์ติดต่อกลับ | `referrer_phone` |
| F | อีเมล *(ฟอร์มรุ่นเก่าอาจขึ้นว่า "อีเมล (ถ้ามี)")* | `referrer_email` |
| G | อายุผู้ป่วย (ปี) | `patient_age` |
| H | เพศ | `patient_sex` |
| I | ความเร่งด่วน | `urgency` |
| J | ต้องการติดต่อเรื่องอะไร | `referral_type` |
| K เป็นต้นไป | คำถามเฉพาะกลุ่ม | ตามคอลัมน์ที่ระบุใน FORMS_AND_SHEETS.md |

> **ลำดับคอลัมน์จริงอาจต่างจากตารางนี้** ขึ้นกับลำดับที่ใส่คำถาม
> ให้ดูที่ข้อความหัวคอลัมน์เป็นหลัก ไม่ใช่ตัวอักษรคอลัมน์

**⚠️ ข้อควรระวังต่อเนื่อง:** ถ้าแก้คำถามในฟอร์มภายหลัง Google อาจเขียนหัวคอลัมน์ทับ
ให้รัน `runSelfTest()` ทุกครั้งหลังแก้ฟอร์ม — ระบบจะเตือนถ้าพบหัวคอลัมน์ภาษาไทยหลงเหลือ

## ขั้นที่ 7 — ให้ dashboard อ่านชีตได้ (service account)

ขั้นนี้ทำให้หน้า `/dashboard` แสดงข้อมูลจริงแทนข้อมูลตัวอย่าง

1. เปิด [console.cloud.google.com](https://console.cloud.google.com)
2. สร้างโปรเจกต์ใหม่ ชื่อ `sibmt-refer`
3. ไปที่ **APIs & Services → Library** → ค้นหา `Google Sheets API` → กด **Enable**
4. ไปที่ **APIs & Services → Credentials → Create Credentials → Service account**
   - ชื่อ: `sibmt-refer-reader`
   - Role: **ไม่ต้องเลือก** (เราจะให้สิทธิ์ที่ระดับไฟล์ชีตแทน ซึ่งแคบกว่า)
5. กดเข้าไปที่ service account ที่สร้าง → แท็บ **Keys → Add key → Create new key
   → JSON** → ไฟล์จะดาวน์โหลดมา
6. เปิดไฟล์ JSON จะเห็นค่า `client_email` และ `private_key`
7. **กลับไปที่ Google Sheet → กด Share → วาง `client_email` → เลือกสิทธิ์ Viewer → Send**
   - ขั้นนี้ห้ามลืม ไม่งั้นจะอ่านชีตไม่ได้แม้ตั้งค่าถูกทุกอย่าง
   - ให้สิทธิ์ **Viewer เท่านั้น** ตามหลักให้สิทธิ์น้อยที่สุด (PDPA-004)
8. คัดลอก **Sheet ID** จาก URL ของชีต (ส่วนระหว่าง `/d/` กับ `/edit`)
9. สร้างไฟล์ `.env.local` ที่ root ของโปรเจกต์ (ดูตัวอย่างใน `.env.example`)

```bash
GOOGLE_SERVICE_ACCOUNT_EMAIL=sibmt-refer-reader@xxxx.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n"
GOOGLE_SHEET_ID=1AbCdEfGh...
```

> `GOOGLE_PRIVATE_KEY` ต้องใส่ในเครื่องหมายคำพูด และคง `\n` ไว้ตามที่อยู่ในไฟล์ JSON
>
> **ห้าม commit ไฟล์ `.env.local` หรือไฟล์ JSON ลง repo เด็ดขาด**
> ตอน deploy บน Cloudflare Pages ให้ใส่ค่าเหล่านี้ที่ Settings → Variables and Secrets

10. รัน `npm run dev` แล้วเปิด `/dashboard` — ป้ายเหลือง "กำลังแสดงข้อมูลตัวอย่าง" ต้องหายไป

| Dashboard ยังขึ้นป้ายเหลือง | ยังไม่ได้ตั้ง env หรือลืม share ชีตให้ service account | ทำขั้นที่ 7 ข้อ 7 และ 9 |
| Dashboard ขึ้นป้ายแดง error 403 | ยังไม่ได้ share ชีตให้ service account | Share ชีตให้ `client_email` เป็น Viewer |
| แจ้งเตือนเคสค้างเร็วเกินจริง | ยังไม่ได้กรอกวันหยุดในชีต `holidays` | ทำขั้นที่ 5.1 |
| Trigger ไม่ทำงาน | timezone ของโปรเจกต์ไม่ใช่ Bangkok | ทำขั้นที่ 5 ข้อ 4 แล้วรัน `setupTriggers` ใหม่ |
