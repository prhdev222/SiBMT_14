# Apps Script — ระบบหลังบ้าน

โค้ด Google Apps Script สำหรับ Google Sheet ของระบบส่งต่อผู้ป่วยนอกโลหิตวิทยา

โครงสร้างชีตและฟอร์มดูที่ [../docs/FORMS_AND_SHEETS.md](../docs/FORMS_AND_SHEETS.md)

---

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `Config.gs` | ค่าตั้งต้นทั้งหมด — แก้ที่นี่ที่เดียว |
| `Util.gs` | เข้าถึงชีตแบบอิงชื่อคอลัมน์ และการนับเวลาทำการ |
| `OnFormSubmit.gs` | สร้าง referral ID, บันทึก consent, ตรวจเคสซ้ำ |
| `Sla.gs` | คำนวณเวลาที่ใช้ไป และส่ง Red Alert |
| `Notify.gs` | ส่งข้อความ LINE (รอบ 10:00 น. และแจ้ง fellow) |
| `Retention.gs` | ถอดชื่อย้ายเข้าคลังเมื่อครบกำหนด |
| `Stats.gs` | สรุปสถิติรายเดือน |
| `Setup.gs` | ติดตั้งครั้งแรกและตรวจความพร้อม |
| `Api.gs` | รับคำสั่งจาก dashboard (จองคิว บันทึกคำตอบ) และแยก request ของ LINE ออกไป |
| `LineWebhook.gs` | บอท LINE — ตอบสถานะเคสเมื่อพิมพ์รหัสอ้างอิง และบอก group ID ด้วย `#id` |

## ⚠️ LINE Notify ปิดบริการแล้ว

เอกสารข้อเสนอโครงการฉบับเดิมอ้างถึง **LINE Notify** ซึ่ง**ยุติการให้บริการไปแล้วเมื่อ 31 มีนาคม 2568**

โค้ดชุดนี้จึงใช้ **LINE Messaging API** แทน ซึ่งต่างจากเดิมตรงที่:

- ต้องสร้าง **LINE Official Account** และ **Messaging API channel** ที่ LINE Developers Console
- ใช้ **Channel Access Token** แทน Notify token
- ต้องรู้ **group ID** ของกลุ่มปลายทาง (ไม่ใช่แค่เชิญบอทเข้ากลุ่มเหมือน Notify)

สอดคล้องกับมติที่ให้สร้าง LINE OA ใหม่อยู่แล้ว

## ขั้นตอนติดตั้ง

### 1. เตรียม Google Sheet

1. สร้าง Google Form ตาม [FORMS_AND_SHEETS.md](../docs/FORMS_AND_SHEETS.md)
2. ในฟอร์ม ไปที่ Responses → เชื่อมกับ Google Sheet ใหม่
3. **เปลี่ยนชื่อชีตคำตอบเป็น `referrals`** (สำคัญ — โค้ดอ้างชื่อนี้)
4. เปลี่ยนชื่อหัวคอลัมน์ให้ตรงกับที่ระบุใน FORMS_AND_SHEETS.md §9.2
   เช่น เปลี่ยน "โรงพยาบาลต้นทาง" เป็น `referrer_org`

> หัวคอลัมน์ต้องตรงเป๊ะ เพราะโค้ดอ้างอิงด้วยชื่อ ไม่ใช่ตำแหน่ง
> (ตั้งใจออกแบบแบบนี้ เพราะ Google Form จะแทรกคอลัมน์ใหม่เมื่อเพิ่มคำถาม
> ถ้าอิงตำแหน่งจะพังทันที)

### 2. ใส่โค้ด

1. ใน Google Sheet เลือก Extensions → Apps Script
2. สร้างไฟล์ตามรายการด้านบน แล้วคัดลอกเนื้อหาจากโฟลเดอร์นี้ไปวาง
3. ตั้ง timezone ที่ Project Settings → Time zone → `(GMT+07:00) Bangkok`

### 3. สร้างชีตที่เหลือ

รัน `setupSheets()` จากเมนู Run — จะสร้าง `advice_library`, `stats_monthly`,
`status_log`, `holidays`, `config` และเพิ่มคอลัมน์ระบบใน `referrals` ให้อัตโนมัติ

> **ตารางออกตรวจ fellow ไม่ได้อยู่ในไฟล์นี้** — อยู่ Google Sheet คนละไฟล์
> ตั้งค่าด้วย `node scripts/setup-schedule-sheet.mjs` ดู
> [docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md) §ไฟล์ชีตตารางเวร fellow

จากนั้น **กรอกวันหยุดนักขัตฤกษ์ลงชีต `holidays`** (คอลัมน์ A = วันที่)
ถ้าไม่กรอก ระบบจะนับวันหยุดเป็นวันทำการและอาจเตือน Red Alert ผิดพลาด

### 4. ตั้งค่า LINE

ที่ Project Settings → Script Properties เพิ่ม 4 ค่า:

| Key | ค่า |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | Channel access token จาก LINE Developers Console |
| `LINE_TARGET_RESIDENT` | Group ID ของกลุ่มแพทย์ประจำบ้านวอร์ดเคโม |
| `LINE_TARGET_ADMIN` | Group/User ID ของแพทย์แอดมินกลาง |
| `LINE_TARGET_FELLOW` | Group ID ของ fellow transplant |

**ห้าม commit ค่าเหล่านี้ลง repo เด็ดขาด** (SRS NFR-003)

#### หา group ID ได้จากไหน

LINE ไม่มีหน้าจอไหนบอก group ID เลย ทางเดียวคืออ่านจาก webhook ที่ LINE ยิงมา
`LineWebhook.gs` จัดการให้แล้ว:

1. Deploy `Api.gs` เป็น Web app ตาม §7 (ถ้ายังไม่ได้ทำ)
2. LINE Developers Console → Messaging API → **Webhook URL** = Web app URL นั้น
   → กด **Verify** ให้ขึ้น Success → เปิด **Use webhook**
3. เชิญบอทเข้ากลุ่มปลายทาง แล้วพิมพ์ `#id` ในกลุ่มนั้น บอทจะตอบ group ID กลับมาเลย
   (ถ้าบอทไม่ตอบ ให้ดู Apps Script → **Executions** จะเห็นบรรทัด
   `LINE source: group Cxxxxxxxx...` — นั่นคือ group ID เหมือนกัน)
4. ทำครบทั้ง 3 กลุ่ม

**ห้ามปิด Use webhook หลังได้ group ID ครบแล้ว** — เอกสารฉบับก่อนบอกให้ปิดได้
เพราะตอนนั้นบอทยังไม่ตอบโต้อะไร แต่ตอนนี้แพทย์ต้นทางพิมพ์รหัสอ้างอิงเข้ามา
แล้วบอทตอบสถานะให้ (ดู `LineWebhook.gs`) ปิดเมื่อไรความสามารถนั้นหายทันที

> ยังไม่มี LINE OA ก็ทดสอบระบบได้ — ถ้ายังไม่ตั้งค่า ข้อความจะถูกเขียนลง
> Execution log แทนการส่งจริง ทำให้ตรวจเนื้อหาข้อความได้ก่อน

ตรวจสถานะด้วย `showLineConfigStatus()`

### 5. ตั้ง trigger

รัน `setupTriggers()` — จะลบ trigger เดิมทั้งหมดแล้วตั้งใหม่ 6 ตัว

| Trigger | จังหวะ |
| --- | --- |
| `onFormSubmit` | ทุกครั้งที่ส่งฟอร์ม |
| `recalculateSla` | ทุกชั่วโมง |
| `sendRedAlert` | ทุกชั่วโมง |
| `sendDailyBatch` | 10:00 น. ทุกวัน |
| `anonymizeExpired` | วันที่ 1 ของเดือน เวลา 02:00 |
| `buildMonthlyStats` | วันที่ 1 ของเดือน เวลา 03:00 |

`recalculateSla`, `sendRedAlert` และ `sendDailyBatch` จะข้ามการทำงานเอง
เมื่ออยู่นอกเวลาทำการหรือเป็นวันหยุด จึงไม่มีการรบกวนนอกเวลา

### 6. ตรวจความพร้อม

รัน `runSelfTest()` — ตรวจว่า:

- ชีตและคอลัมน์ครบ
- **ไม่มีคอลัมน์ที่ห้ามมี** (ชื่อผู้ป่วย, HN, เลขบัตรประชาชน)
- การนับเวลาทำการถูกต้อง

รัน `verifyLibraryHasNoIdentifiers()` เพิ่มอีกหนึ่งครั้ง เพื่อยืนยันว่า
คลังคำตอบไม่มีคอลัมน์ที่โยงกลับหาผู้ป่วยได้

### 7. Deploy Web app สำหรับ LINE webhook (ไม่บังคับ)

ทำข้อนี้เมื่อจะตั้ง LINE OA — ใช้หา **group ID** ของกลุ่มปลายทาง
ซึ่ง LINE ไม่มีหน้าจอไหนบอกค่านี้เลย

1. Deploy → New deployment → **Web app**
   — Execute as: **Me** / Who has access: **Anyone** (LINE ต้องเรียกได้โดยไม่ล็อกอิน)
2. คัดลอก Web app URL (ลงท้าย `/exec`) ไปใส่ที่
   LINE Developers Console → Messaging API → **Webhook URL**
3. ทำตามขั้นตอนหา group ID ใน §Script Properties ด้านบน

> `Anyone` หมายถึงใครก็ตามที่รู้ URL — แต่ endpoint นี้**ไม่มีคำสั่งเขียนอะไรเลย**
> มีแค่รับ webhook แล้ว log ว่ามาจากกลุ่มไหน ต่อให้ URL หลุดก็ทำอะไรกับข้อมูลไม่ได้

**ตารางออกตรวจ fellow ไม่ผ่านทางนี้แล้ว** — เว็บเขียนลงไฟล์ชีตตารางเวร
ของตัวเองโดยตรง เพราะ Apps Script Web App ใช้เวลา 1–10 วินาทีต่อคำสั่ง
เทียบกับ Sheets API ที่ราว 400 มิลลิวินาที ดูวิธีตั้งไฟล์ใน
[docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md) §ไฟล์ชีตตารางเวร fellow

## จุดที่ออกแบบไว้เป็นพิเศษ

**การนับเวลาทำการ** — นับเฉพาะ จันทร์–ศุกร์ 08:00–16:00 ไม่รวมวันหยุด
ทดสอบแล้วครอบคลุมกรณีขอบ เช่น เคสยื่นเย็นวันศุกร์ 15:00 น. จะนับได้ 2 ชั่วโมง
เมื่อถึงเช้าวันจันทร์ 09:00 น. ไม่ใช่ 66 ชั่วโมงแบบนับปฏิทิน

**ไม่มีช่องทางฉุกเฉิน** — ตามมติอาจารย์ ไม่มีการข้ามรอบแจ้งเตือน 10:00 น.
ยกเว้น Red Alert ซึ่งเป็นตาข่ายนิรภัยชั้นสุดท้ายเมื่อเคสค้างครบ 3 วันทำการ

**ตรวจเคสซ้ำโดยไม่ใช้ชื่อและ HN** — เทียบจากเบอร์แพทย์ผู้ส่ง + อายุ + เพศ
หรือโรงพยาบาล + อายุ + เพศ + กลุ่มโรค ภายใน 30 วัน
ระบบ **flag ให้ตรวจสอบเท่านั้น ไม่รวมเคสอัตโนมัติ** เพราะสัญญาณเหล่านี้ไม่ยืนยันตัวบุคคล

**ถอดชื่อแทนการลบ** — เมื่อครบ 12 เดือนหลังปิดเคส ระบบย้ายเข้า `advice_library`
โดยลบ referral ID, ข้อมูลผู้ส่ง, วันที่แบบเต็ม และแปลงอายุเป็นช่วงอายุ
ทำให้เก็บองค์ความรู้ไว้ถาวรได้โดยไม่เหลือข้อมูลส่วนบุคคล

**LockService ตอนสร้าง referral ID** — กันกรณีส่งฟอร์มพร้อมกันหลายคนแล้วรหัสชนกัน

## ทดสอบก่อนใช้จริง

ทำกับ **Google Sheet ชุดทดสอบแยกต่างหาก** อย่าทดสอบบนชุดจริง (NFR-003)

- [ ] ส่งฟอร์มทดสอบครบทั้ง 4 กลุ่ม — ตรวจว่า referral ID ไม่ซ้ำ และสถานะเริ่มต้นถูก
- [ ] กลุ่มที่ 4 ต้องได้สถานะ `Auto Replied` ทันที
- [ ] ส่งฟอร์ม 2 ครั้งด้วยเบอร์ อายุ เพศเดียวกัน — ต้องขึ้น `possible_duplicate_of`
- [ ] แก้ `submitted_at` ย้อนหลังให้เกิน 16 และ 24 ชั่วโมงทำการ (2 และ 3 วันทำการ) แล้วรัน `recalculateSla()`
      ตรวจว่า `alert_level` เปลี่ยนเป็น yellow และ red ถูกต้อง
- [ ] รัน `sendDailyBatch()` ด้วยมือ ตรวจข้อความใน Execution log ว่า**ไม่มีข้อมูลผู้ป่วย**
- [ ] ตั้ง `closed_at` ย้อนหลังเกิน 12 เดือน แล้วรัน `anonymizeExpired()`
      ตรวจว่าแถวย้ายเข้า `advice_library` และ**ไม่มี referral ID ติดไปด้วย**
- [ ] รัน `buildMonthlyStats()` ตรวจตัวเลขกับข้อมูลจริง
